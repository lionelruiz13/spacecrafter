Two things worth knowing before ratifying:
- **`light_source` grants everything `isStar()` grants**, not only light emission: satellite-ness of its children, the magnitude branch, hint suppression, grid tropics, big-halo + `StarLoader`, both shadow-sweep exclusions, `getSatellitesFov`, `system_star` auto-detection, and the day-length info line. If the name should promise only illumination, the key wants a different name (e.g. `star`), not a narrower meaning.
- **`shadow_exempt` names the only LIVE half of `MINOR_BODY`**: the mass-instanced half has no consumer yet (`instanced` was deliberately left unparsed until row 5/S4, §11.78(d)). One key is right today; `instanced` is its natural sibling when that consumer lands.
**Cost of a respell is near zero and stays that way**: 4 code sites (two `authored()` reads + the both-declared error in `loadBody`, two emission lines in `generateComposedTwin`), and the keys exist ONLY in the machine-owned `.ini.disabled` twin, regenerated at every legacy load — **no user file needs migrating**, a respell propagates on the next launch. This is the §11.89(a) cheap-veto pattern, deliberately preserved.
