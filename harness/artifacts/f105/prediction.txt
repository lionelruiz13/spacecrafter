(c) THE GUARD, in ModularBody.{hpp,cpp} only:
      - `bool parkedFramePublished = false;` beside `parkedChildFrame`, set in
        `publishParkedFrame` (the one writer, so the two members cannot desync);
      - `useNow()` returns `bool`: true = served.  `!renderHidden || !parent`
        returns true (fresh by construction).  A hidden body is served iff its
        parent is: a HIDDEN parent iff `parent->useNow()` said so, a non-hidden
        parent iff `parent->parkedFramePublished`.  Unserved => LOG ONCE and
        return false BEFORE any refresh, so the readout keeps its unevaluated
        value instead of gaining a wrong one;
      - `bool unservedLogged` beside it, the once-per-body flag;
      - the dump's call stays.
    Callers ignore the new return value, so the widening is invisible to them
    (I1).
RISK NAMED IN ADVANCE: the guard is placed BEFORE the memo test, so a body
parked in the CURRENT frame whose parent has not published yet would be refused
where the old code returned "fresh" at the memo.  On this corpus that window
does not exist (every parent is walked every frame before any dump), and P5's
"exactly 8" is the check that would catch it: a 9th line would name the body it
happened to.
