--------------------------- (G) THE INSTALL PREFIX DOES NOT REACH THE BINARY
 An unstated premise of this task, found by reading:
   src/spacecrafter.hpp:44   #define CONFIG_DATA_DIR "/usr/local/share/spacecrafter/"
   src/spacecrafter.hpp:45   #define LOCALEDIR       "/usr/local/share/locale/"
 They are HARDCODED #defines with no #ifndef guard, and no CMake code sets or
 configures them (grep: CONFIG_DATA_DIR appears in CMakeLists.txt zero times).
 main.cpp:186 reads the macro into `dataRoot` and main.cpp:246 logs it as
 "ROOT   DIR:".  Therefore:
   * -DCMAKE_INSTALL_PREFIX moves WHERE THE FILES GO and nothing else;
   * a binary installed into a scratch prefix still reads
     /usr/local/share/spacecrafter/ at runtime;
   * the task's check (a) -- "the applog's data-root path proves the scratch
     binary runs from the scratch prefix" -- CANNOT pass as written, and the
     applog line is exactly the instrument that shows why.
 Consequence for the INSTALL rewrite: a "scratch prefix instead of sudo"
 instruction would be WRONG unless it also said that the data root is fixed at
 compile time.  The honest non-sudo instruction is: run the binary from the
 build directory, with the data root already populated at /usr/local.
