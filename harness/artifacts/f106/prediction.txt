8. THE FIX'S SHAPE, FIXED BEFORE IT IS WRITTEN
----------------------------------------------
A `--commit-filter` mode beside --emit-env and --msg-filter, same self-invocation
pattern, $SELF absolute.  It reads the filtered message from stdin with the
`cat; printf X` sentinel, reads the ORIGINAL object with `git cat-file commit
$GIT_COMMIT`, splits it at the FIRST truly empty line (a gpgsig block's own blank
lines are indented by one space -- verified on cebebf44 -- so they are not that
line; this is the same split filter-branch itself makes at :465-474), and emits
`printf '%s' "$GIT_COMMIT"` when ALL FIVE of the fields a signature signs are
unchanged: tree, parents (in order), author ident, committer ident, message
(byte-exact).  Otherwise `git commit-tree "$@"` with the message on stdin, as
today -- and if the original object carried a `gpgsig` header, one line is
appended to $SIG_DROPPED first.
  Deliberate departures from the mandate's letter, both strictly conservative:
  (a) FIVE fields, not three.  11.227(b) says a signature signs "the whole
      commit object -- tree, parents, author, committer, message"; comparing
      three of the five would let a --tree-filter or a committer rewrite emit
      the original id for a commit that is NOT the original -- a silently WRONG
      history instead of a silently shortened one.  Today both extra fields are
      inert by construction (no tree/index/subdirectory filter is passed, so
      filter-branch hands over $commit^{tree} verbatim -- git-filter-branch:373
      and :490; the env-filter exports GIT_AUTHOR_NAME only), which P2 measures.
  (b) the parents are read from the ORIGINAL OBJECT's `parent` lines rather than
      from `git rev-parse "$GIT_COMMIT"^@` -- the same information from the same
      bytes, one subprocess fewer per commit, and no root-commit edge case.
      Proved equivalent over the whole fixture range offline.
