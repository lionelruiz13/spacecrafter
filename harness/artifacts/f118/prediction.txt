0.  THE MECHANISM THIS TASK MEASURES, re-resolved at HEAD (every line checked)
=============================================================================

`ssystem_factory.hpp:359-370` is the DUAL-PATH MIRROR of `body name X hidden
true|false`: after the old path's `ProtoSystem::setPlanetHidden`, it calls
`ModularBody::hide()` / `show()` on the new path's body.  (Verified at HEAD:
without this mirror the new-path walker would be unreachable from the command
surface and this task would have no channel at all.)

`ModularBody::show()` (ModularBody.cpp:794-826), in this order:
   1. relation restored, parent list re-entered, cached state invalidated;
   2. `useNow()` (:812) -- renderHidden is STILL SET here, deliberately, so the
      D8 barrier does its full work: 1 + RESUME_EXTRA_ITERATIONS = 5 calls of
      `recursiveTranslationUpdate` at the current date (ModularBody.cpp:562-564),
      i.e. 10 solver steps.  THE SEED ENDS CONVERGED AT THE FRAME'S DATE.
   3. `propagateRenderHidden` (:817) -- the flag clears;
   4. `resumeModulesAfterHidden()` (:821) -- every module of the subtree.

Of the three modules that override `resumeAfterHidden`, TWO only snap a fader
(`OrbitModule.hpp:101-108`, `HintModule.hpp:78-80`).  EXACTLY ONE touches the
solver: `TrailModule::resumeAfterHidden` (TrailModule.cpp:169).  Its
reconstruction loop (:227-237) calls
`orbit->positionAtTimevInVSOP87Coordinates(date, sampleJD, tmp)`, which for an
`EllipticalOrbit` is `positionAtTime(JD)` (orbit.cpp:466-468) and therefore
`eccentricAnomaly(meanAnomaly, iterativeLastE)` (orbit.cpp:582) -- THE BODY'S
OWN POSITION SEED, not the batch seed F111 gave the sampler.  So the walk drags
the just-converged seed BACK to the last reconstructed sample's date,
`lastJD + missed*deltaTrail`, and leaves it there.

The body's next evaluation is `transformParentToBodyPos` (ModularBody.hpp:674-711,
`++evalCount` at :709), one call = ITERATIVE_STEPS_PER_CALL = 2 steps
(iterative_orbits.hpp:31).  AT A PINNED CLOCK every later frame asks for the same
mean anomaly from wherever the previous call left the seed, so the residual
CONTRACTS geometrically.  On the `e < 0.2` fixed-point branch (orbit.cpp:519-525)
the per-step factor is `e*cos(E)`; per FRAME it is that squared.

FRAME ORDER, which is what makes k meaningful.  `App::update` runs
`scriptMgr->update` (app.cpp:796), then `updateFromSharedData` (:801, which
drains the WHOLE tcp queue in a do/while), then `executor->update` (:817) -- the
walk.  `App::draw` runs afterwards, and `ModularSystem::drawTrails`
(ModularSystem.cpp:658) is where `TrailModule::update`/`accumulate` live.
Therefore:
  * a dump command in the SAME frame as the unhide runs BEFORE that frame's
    walk and reads `useNow`'s CONVERGED position -- k = 0 carries nothing;
  * the first dump AFTER one intervening walk carries the full transient.
k is defined here as the dumped `evalCount` delta from the last pre-unhide dump,
and is MEASURED, never assumed (discriminating check (b)).

deterministically.  The range's upper end allows for a `dual_dump` write that
