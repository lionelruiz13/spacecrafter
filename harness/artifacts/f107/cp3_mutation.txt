  THE MECHANISM: `ModularBody::isSystemCentered()` (ModularBody.hpp:1788-1800)
  answers by POSITION -- it walks up the chain and returns false only if some
  ancestor's `eclipticPos` has a non-zero component -- and BOTH orbit loaders
  ask it at LOAD TIME to decide whether to fold the parent's rotation into the
  orbit (ElipticOrbitLoader.hpp:12, CometOrbitLoader.hpp:14).  Mutant 1 leaves
  every body's `eclipticPos` at (0,0,0) during the load, so every parent reads
  as system-centred and every child's orbit is built in the WRONG FRAME.
  **So the constructor's JD-0 evaluation has a SECOND consumer: it is what makes
  `isSystemCentered()` answer correctly while the system is still loading.**
  That is a fact about the code the task did not set out to find, and it is what
  makes "skip the evaluation at JD 0" unusable as a fix shape.
