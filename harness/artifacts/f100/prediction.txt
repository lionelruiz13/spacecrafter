0.  THE MODEL UNDER TEST  [derived, from the source read below]
--------------------------------------------------------------------------
A parked body's eye-frame position has exactly ONE writer: the D8 use-site
barrier ModularBody::useNow() [observed: ModularBody.cpp:455-481], which
early-returns when

    evaluatedJD == currentJD                    [observed: ModularBody.cpp:459]

`evaluatedJD` is stamped by the translation refresh itself
[observed: ModularBody.hpp:683, :857] and `currentJD` is the frame's SIM date,
written once per frame at the walk's entry [observed: ModularBody.cpp:375].
The frame the refresh consumes is the parent's published flat frame
[observed: ModularBody.cpp:466-478 -> publishParkedFrame, ModularBody.hpp:1003-1007],
and that frame descends from Camera::viewMat() [observed: Camera.cpp:723,:734],
i.e. it FOLLOWS THE CAMERA.

So the memo key is complete for `eclipticPos` (a function of the date alone)
and INCOMPLETE for `mat` (a function of the date AND the camera).  At a pinned
clock the first use at a date refreshes `mat`; every later use returns at :459;
the camera moves on without it.

THE FIX SHAPE THIS PREDICTS (stated now so it cannot be retrofitted): the early
return must also compare the FRAME the last refresh consumed; the +4
re-convergence iterations stay bound to a DATE change (the Kepler seed is
date-driven [observed: ModularBody.hpp:1015-1023]), and a frame-only change is
ONE translation refresh.
