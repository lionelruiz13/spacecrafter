    - **(c) INTRINSIC — present on day one or two, before any failure or teacher** [read]:

      2. **POOLING / RING REUSE.** The alpha creates and deletes canvas items per obstacle; 1.0 pre-creates 40 + 40 + 5 rectangles and ROTATES the lists (`obstacles = [obstacles[-1]] + obstacles[0:-1]`) — a ring of reused items, within the first week. Same shape as `Fox::storage` (2023), `BufferMgr` sub-allocation (2021), the video ring of §11.276-278.
      3. **DATA-FORMAT COMPATIBILITY, BOTH DIRECTIONS.** From 2.x a level file carries a version; the reader does `try: level, version = level ... except: version = 2.0` (every older file, versionless included, is accepted forever) and REFUSES a file newer than itself with a dialog naming the version required (`Le cube 3.0 released.py:448-456`; the lib at 4.1: `Le_cube_lib.py:586-598`). D9's frozen field and D13's "downgrade must stay possible", at 2017-12, with nothing to stand on.
      4. **PARAMETERS OUT OF THE CODE.** `Elements_globaux.config` (2018-03): sizes, speed, colours, key bindings read by `eval(Globals.read())` (`Le_cube_lib.py:15`); a missing file prints *"Veuillez ouvrir le cube éditeur pour initialiser les paramètres par défaut"* — the editor writes the defaults, the game reads them: one writer.

    - **(d) LEARNED — the ladder, each rung dated with the need that forced it** [read]:
      1. **1.0 (2017-03-18): copy by KIND.** Three obstacle kinds = three parallel triplets (`obstacles/obs_x/obs_y`, `...1`, `...2`) and three copied loops (40 / 40 / 5 iterations); five `def`, none with a parameter, every function opening with a `global` line.
      2. **2.0 (2017-05-30, +21 `def`): the copies become FUNCTIONS, still one per index.** `cl1..cl4` / `CL1..CL4` are one-line forwarders to `ouvre_fichier(n)` / `supprime_fichier(n)` — a tkinter callback carries no argument, so one forwarder per index is what the binding API forces: the law is already single, the entry points are many (the S2 shape, imposed by the host).
      3. **3.0 (2018-01-16, +6 -8): per-KIND -> per-EFFECT.** `Sol / Plafond / Portail / Orbe / Special (num, a)` — the kind is now a PARAMETER (`objets[num][1][a]`: the three triplets collapsed into one indexed structure), the function is named for what it does, and the first docstrings appear (*"Sol du niveau pour les blocs, bloc principal"*). I4 — behaviour belongs to the type — reached in ten months with no teacher; this is the exact move of EntityCore's `79c691e` (ten parallel vectors -> one `vector<QueueFamily>`) three years earlier.
      4. **3.4 (2018-03-07, the `Version 4.x` folder): the LIBRARY split — the first structural rework, and its need.** `Le_cube_lib.py` takes 25 of the game's 25 `def` and 2 of the editor's, adds 6 (`Tester`, `Choisir`, `Créer_niv`, `Valider_nouveau_niveau` ...); `Le cube play.py` becomes SIX lines (`from Le_cube_lib import Valeurs, Choisir, Fenetre_de_jeu`); the editor does `from Le_cube_lib import *` and defines ZERO names the lib defines. The game/editor text duplication had been tiny (2 shared names, `clic` / `declic`); what forced the split is a NEED — the editor had to RUN the level it edits (`Tester`), so the game's law had to live where both could reach it (I2: the lowest common node). Same week: files organised into version folders, data files given extensions at 3.5 (`niveau` -> `nouvel essai.cubelvl`, `Elements_globaux` -> `.config`, `Blocs.lib`) — the file organisation he says he learned then.
      5. **3.4 / 3.5: BEHAVIOUR AS DATA.** `Blocs.lib` = `[[type, prioritaire, action-source], ...]` — seventeen blocks, each action a Python snippet (`'global saut\n    saut = 3.2'`, `'global inverse, saut\n    inverse = not inverse\n    saut = -saut'`); the lib runs `exec("def Action():\n    " + Les_blocs[r][2])` (`Le_cube_lib.py:775`) and orders the blocks by a PRIORITY class (`Type_prioritaire / Prioritaire / Autres`, lines 262-296; the lib's own changelog line 3: *"Ajout du système de priorité"*). A block's effect is editable without touching the program — Phocan's "Flexible Operation eXecutor" five years before it, with `exec` where Phocan compiles opcodes. And the grammar of the data file is written as a comment block at the lib's end (`:721-727`, *"Les_blocs = Fichier.read() --> [[Type, si_prioritaire, action], ...]"*): the format IS the specification, stated once — I8's premise, at 2018.
      6. **The first `class` (2018-03): a state holder.** `class Valeurs: encore = True` — two lines, a namespace to share a flag between the lib and `play.py`, replacing a `global`. Behaviour never went into classes here; `global` statements persist to the end (29 in the lib, the longest 250 characters).

    - **(g) WHAT THIS ANSWERS, IN HIS THREE TERMS** [derived]. *What is intuitive as a beginner*: content as data with the editor first, pooling, format compatibility with a fallback for the old and a refusal of the new, parameters in a file — all present within the first year, none taught. *What was learned faster*: the copy -> per-kind function -> per-effect function -> behaviour-as-data ladder, four rungs in twelve months, each rung forced by a need (many levels -> the menu; many kinds -> the parameter; testing from the editor -> the shared library; custom blocks -> the block file). *The approach with nothing to stand on*: the same as today's minus loudness — put the variable part in data, keep one law and forward to it, move the law to where every consumer reaches it — and the one thing the origin does not have is the failure signal, which the later corpora show arriving with the instruments built on the day of a failure (11.279(f)).
