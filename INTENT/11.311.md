## (1) THE ORDER SURFACE - F142's input [derived from (3)(b)-(d) below; names flagged, his]

The movement control holds THREE place orders - lat, lon, height - each with two slots: a HELD value (keys and commands write it; the last writer wins; 0 is the stop) and a SAMPLED value (the joystick writes it each frame it is deflected; the control clears it after use). Per frame the control reads `clamp(held + sampled, -1, 1)` per axis, cubes it, scales it by `velocityScaling(dt)` through the gate and sends the final measure to both engines with delay 0 (see (3)(b)).

- **The native orders (what a key's `-` default does under B49):** press -> `Core::moveLat(+1)` (SHIFT+KP_8), `moveLat(-1)` (SHIFT+KP_2), `moveLon(+1)` (SHIFT+KP_6), `moveLon(-1)` (SHIFT+KP_4); release of the BASE key, whatever the modifier state then -> `moveLat(0)` / `moveLon(0)` (K-3 of 11.305(f): the release fires symmetrically to the press that armed it - the stop must not test SHIFT). The joypad buttons keep `Core::raiseHeight(1|0)` / `lowerHeight(1|0)` (press / release, per-sign stop as `turnLeft` / `turnRight`). No key carries a height order (K8 of F133 stands; 11.273: his keyboard is fully allocated) - a show or a binding reaches it by the commands below.
- **The commands (N6, default yes - "everything shall be script-reachable"):** `camera action move_lat value <v>`, `camera action move_lon value <v>` with v in [-1, 1], `camera action raise_height value <v>`, `camera action lower_height value <v>` with v in [0, 1]; the value is HELD until the next value on that axis; `value 0` is the stop; a missing `value` is an error (S11), never a silent stop. A show holds a move with three lines: `camera action move_lon value 1` / `wait duration 3` / `camera action move_lon value 0` - deterministic in TIME (wall-clock, 11.307(d)), not in DISTANCE (the law scales with the altitude along the way): a show that wants an exact displacement writes `moveto delta_lon <deg> duration <s>` as today - the deterministic concern of 11.293(a), untouched.
