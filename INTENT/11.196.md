## (a) The headline is an artifact, not a sentence: the engine's own recording of a broken show

`AppCommandInterface::executeCommandStatus` calls
`scriptInterface->recordCommand(commandline)` on the SUCCESS branch and nowhere
else `[observed: app_command_interface.cpp:1310-1312 at ba7a32a8]`. So a
recording taken while a bad script plays **is** the list of lines the engine
reported success for — the boolean §5.116 says is always `true` for a coerced
value, materialised on a shipped channel instead of argued from source.

Twenty-two lines were played from a file. Here is what the engine wrote back
`[measured: artifacts/f77/live/played/f77_record.sts]`, the recorder's own
`wait duration` interleaves removed for reading:

```
script action play filename <PLAY>/f77_bad.sts
flag atmosphere yes          <- coerced to OFF, recorded
flag atmosphere 1            <- the toggle, written back with the value it ended at
flag atmosphere on           <- the accepted control, recorded
flag atmosphere 0
flag atmosphere Off          <- coerced to OFF, recorded
flag atmosphere 1
set moon_scale big           <- coerced to 0, recorded
set stall_radius_unit = 5.0  <- coerced to 0, then DROPPED, recorded
configuration ... f77_sl_on.txt binary_mode on     <- `on` read as NO, recorded
configuration ... f77_sl_true.bin binary_mode true
configuration ... f77_sl_off.txt binary_mode off

```

**`flag nosuchflag on` — line 21, the one line the engine refused — is absent.**
Five silently coerced lines are re-emitted verbatim, as good lines, in a file a
user would take for a faithful record of the show; the only line the recorder
drops is the one the log already complains about. §5.116's *"the command reports
SUCCESS"* is no longer derived from a `debug_message` that was never assigned:
it is written on disk by the engine, in the engine's own words.

Two riders worth naming, both visible in that block. The toggles are
NORMALISED (`commandFlag` rewrites its own commandline with the value the flag
ends at `[observed: :1343-1356]`), so a re-play of the recording would not
reproduce the coercion — it would reproduce its RESULT. And the recorder is
§5.96's subject: what it persists is the line as parsed, so a show recorded from
a broken show inherits the breakage in exactly the places the engine could not
see it.

## (g) §5.117's CONSOLE half — the clause was wrong, and wrong in the ledger's favour

§5.117 says: *"`print_log = true` in the installed `config.ini` and `cLog` at
`L_ERROR` already writes `std::cerr`, so promoting these 157 records also puts
them on the console"*. Reading `cLog::write` `[observed: log.cpp:122-124]`:
`if (isDebug) writeConsole(texte, type);` runs for **every** line at every
severity, before the severity tag is even chosen; `writeConsole` then sends
`L_ERROR`/`L_WARNING` to `std::cerr` and **everything else to `std::cout`**
`[observed: log.cpp:204-208]`. `isDebug` is `[debug] print_log`
`[observed: main.cpp:262]`, shipped `true` `[observed: ~/.spacecrafter/config.ini:309,
checkConfig.cpp:68]`.

Measured, with the child's two streams captured SEPARATELY (which is why
`f27_reply.Session` gained a default-inert `stderr_path` — a merged capture
cannot tell "reached the console" from "reached the ERROR console")
`[measured: artifacts/f77/live/console-excerpt.txt]`:

| | stdout | stderr |
|---|---|---|
| lines | **2161** (1178 Debug, 749 Info, 234 untagged) | **247** (215 Warn, 29 Error, 3 untagged) |
| the two refusals (`L_DEBUG`) | **both** | **0** |
| the ruled-class report (`L_ERROR`) | 0 | **1** |

**CORRECTION: the 157 refusals ALREADY reach a console under the shipped
default.** They reach stdout. A promotion to `L_ERROR` would MOVE them to
stderr and colour them red — it would not put them on a console they were
absent from. That is a materially different fork for the owner: the question is
not *"should a refusal appear on the console"* (it does), it is *"should a
refusal appear where a shell operator's `2>` catches it"*.

**The price, cited and not re-derived** (F76, SIGNAL column of
`artifacts/f76/dispositions.tsv.gz`): over the 408 installed scripts, **12** of
the 1661 findings make the engine write an `L_DEBUG` refusal, **2** are already
`L_ERROR`, and **1647** are silent. So a full corpus play moves **12** lines
from stdout to stderr. Twelve.

**And the burial is now a console number too.** In this short run the two
refusals sat among 2161 stdout lines — the `Execute_command` echo alone
contributed 48 of them in the script log and 749 `L_INFO` lines to stdout. The
fault-to-trace ratio §5.117 argues about for the FILE is the same ratio on the
console, by construction, because the console echo is unfiltered.

## (n) What the next task must know

1. **The recorder is a success channel.** `script action record` +
   `cancelrecord` around anything gives the engine's own list of what it
   reported success for, with no photometry and no source reading. The spelling
   is `cancelrecord` (F76); a second `record` is a STOP.
2. **`configuration action save` is a shipped readout for part of the state.**
   It writes `[viewing] moon_scale`, `[landscape] flag_atmosphere` and ~90 other
   keys from live values `[observed: core.cpp:1693-1760]` into
   `$HOME/.spacecrafter/config.ini` — the FARM's copy under a temp-HOME, so it
   is safe. **It is not a general readout**: keys `saveCurrentConfig` does not
   set (e.g. `stall_radius_unit`) are re-emitted from the value that was LOADED,
   which reads exactly like a live value and is not one. Check the setter list
   before trusting a key.
3. **A merged applog cannot answer a console question.** `Session(...,
   stderr_path=...)` splits the streams; the default is unchanged.
4. **`Error executing ` at FILE origin carries the FULL PATH.** A matcher that
   expects a basename will miss it.
5. **A funnel refusal does not write the file.** Only `reportScriptError`
   annotates. Any gate asserting "the log showed a tail" must not conclude "the
   file has one".
6. **Still owed at §5.117 after this task**: nothing that a launch can pay. Both
   its owed halves are measured (the file-origin shape, the console side). What
   remains is the owner's fork: severity vs channel, now with the corrected
   console fact and the number 12.
