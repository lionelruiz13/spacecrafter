# INTENT §11.130

130. **§5.63 — THE CAMERA CAME BACK EXACT AND THE SKY CAME BACK FROM SOMEWHERE ELSE (2026-08-01, Opus 5 executor dispatched by Claude Fable 5, task F22; code `170c3ad6` the readback + `4d31e9d0` the attribution's fix + `42ec495a` row B10 on both paths + `ff2c798b` the fixed point; harness `4bbce4f` + `acc7a52` + `39581b2` + `1c65d53` + this entry).** The row was owed one probe and it named it: *"a readback of the old path's own view state … which does not exist today"*. Built, and it answered in one run. The restored session reproduced **every field of `Camera::dumpTrace` to the digit** and drew its sky from a direction **107.634° away**, against an in-scene A/A floor of **1e-6°**. §5.63 is **CLOSED**; **b31-design §6.2 T1 is MET**; B31's open set drops to three.

    - **(a) THE READBACK, AND WHY IT IS AN INSTRUMENT AND NOT A RENDER CHANGE.** The dual dump's header gains one `oldView` object, written by the four owners of the state the old sky is drawn from and composed by the one object that has all four: `Navigator::dumpTrace` (the three vision vectors the row names by hand, heading, view offset + its ramp, viewing mode, the two lock/track flags, the in-flight plans, and five frame transforms including `mat_local_to_earth_equ`), `Observer::dumpTrace` (place, anchor, the quaternion rotator that multiplies `getRotEquatorialToVsop87` from INSIDE the equatorial frame, the place plan), `Projector::dumpTrace` (fov, aim fov, viewport, and **`unprojectViewport` itself** — the convex region `HipStarMgr::preDraw` hands the geodesic grid, i.e. the thing that decides WHICH STARS EXIST this frame), `HipStarMgr::dumpTrace` (**`nbStarsToDraw`** — how many stars the old path actually drew — the search level, the faders, and the `MagConverter` terms `fov_factor`/`min_rmag` that scale every star's radius), and `Core::dumpOldViewState` for what only Core knows: the two photometric inputs and **the refraction DECISION the star draw is handed** (`atmosphere->getFlagShow() && FlagAtmosphericRefraction`, one expression rather than two facts about it). Every method is `const`, computes nothing, caches nothing, and is reachable only from the dump channel — the old render path is unchanged by construction (§11.52(b)), on F20's T2 gap-dump precedent. `SSystemFactory::dumpTracePaths` gained an injection point rather than an export of anybody's internals (I1/I2). `[observed: navigator.cpp, observer.cpp, projector.cpp, hip_star_mgr.cpp, core.cpp; code 170c3ad6]`
      **One instrument defect fell out of its own first run and is fixed in it**: the dump emitted bare `inf` for a plan coefficient whose duration is 0 (speed = 1/0), which is not JSON — every consumer of the channel failed on the whole line. The value is preserved as a quoted token rather than nulled, because *"this plan is instantaneous"* is exactly the state a restore has to get right.

    - **(b) WHAT DISCRIMINATION MEANS HERE, AND THE ONE CONTROL THAT DOES NOT APPLY.** `[measured: harness/f22_s563_view.py, artifacts/f22view]` The ladder is §11.129's three launches — scene built by commands (saved) / the same scene rebuilt (the in-scene A/A **floor**) / a fresh launch that restores — with the dump and the screenshot taken from the SAME launches, so the field table and the pixel table are one run. A field is a candidate only if it differs saved-vs-restored **and** agrees in the floor.
      * **The floor's own differing set is 26 leaves and every one of them is a CAMERA field** (`alt`, `az`, `lockedSkyRot`, `mat`, ~1e-3) — the sky lock captures at whatever frame the command lands on. **The old-path fields have a floor of zero** (`localVision` agrees between two rebuilds to **1e-6 degrees**), which is what makes them able to attribute anything.
      * **88 candidates**, and they are the whole old-path view: `localVision`/`equVision`/`precEquVision`, `matLocalToEye`/`matEarthEquToEye`/`matJ2000ToEye`, the projector's four unprojected half-spaces, and `nbStarsToDraw` **392 (saved) vs 689 (restored)**.
      * **The dispatch's stars-off control does not discriminate view state, and that is a property of the control, not a failure of the readback** [derived]: turning the stars off removes the CONSEQUENCE. A navigator does not stop holding a direction because nobody drew from it — a "cause" that vanished when you stopped drawing the thing it aims would BE a consequence. Measured: with stars off the screen agrees (43 px>8 against a floor of 48) and 87 of the 88 fields still differ. The one that collapses is `stars.drawIdx`, the next link in the chain. The control that does discriminate is the A/A floor above, and it is the one the criterion rests on. **Said rather than inferred, per the dispatch's own instruction.**

For this member the clause is measurably false: nothing ties `Navigator::local_vision` to the camera, and in a scene where **neither path was ever aimed** the two sit 107.634° apart — the old path at the config's `init_view_pos`, the camera wherever its own defaults put it.       **Fact 2 — a sky lock froze a stale pair, and that is why the magnitude moved every restore (§5.63 exclusion 7).** The whole restore executes inside ONE command with no frame between its steps, so when `flag_lock_equ_pos` goes on, the navigator's transforms and its `equ_vision` are still the ones the PREVIOUS FRAME computed — on the launch body, at the launch place, **at the launch date, which `Core::init` sets from the system clock**. A term whose input is the wall clock is a term that differs on every restore: 3185 / 5655 / 7834 / 7830 / 10116 px, saved side stable at 400/401/401 `[§11.129(b)]`.

    - **(f) A SAVE THAT IS NOT A FIXED POINT IS NOT A SAVE, and this one was not, for one ulp.** `[code ff2c798b]` Under a live sky lock the old navigator round-trips its direction through the local↔equatorial pair every frame, and that round trip settles one double-ulp from wherever it started.     - **(h) THREE THINGS §5.63 SAID THAT THIS RETRACTS OR CORRECTS.** [derived, each from this task's own measurement]
      * **Exclusion (4)'s *"the milky way is in the SAME place in both while the star/DSO field is not"* is retracted as an inference.** The milky way is a smooth full-dome texture: a 107° change of view direction moves it too, but only 744 px cross a >8 threshold, while point sources go positionally disjoint. It was read as evidence that the old view frame had NOT moved. The old view frame is exactly what had moved. **The general lesson: a low-spatial-frequency layer is not a witness for displacement.**
      * **The rotation fit excluded a ROLL, not a change of direction.** A best fit *about the dome centre* over ±180° cannot see a different patch of sky arriving; in a fisheye projection a change of view direction is not an image rotation.
      * **The in-scene A/A floor of a sky-LOCKED scene is not 0.** §11.128(g)/§11.129 recorded 0; measured here at **26 / 44 / 45 / 48 / 49 / 51 px>8** across six runs of two harnesses, and the A/A dump names the reason itself — `alt`, `az` and `lockedSkyRot` differ by ~1e-3 between two launches, because the lock captures at whatever frame the command lands on. The 0 was a property of those runs. §11.80(a)'s rule (measure the floor in-scene, never inherit it) is what keeps this from mattering, and it is why every number above carries its own floor.

    - **(i) OUT-OF-SCOPE FINDS, recorded not fixed.**

Not fixed here: making the seam refresh first changes what a shipped command does in that case, which is user-visible semantics. → **§5.65**.
      * **`CoreLink::lookAt` is a dual seam whose two halves do not land in the same direction** `[measured: 94.4° between the old path's landing and the aim built from the camera's own alt/az]`. It is the B9 az-convention family (§11.4/§11.60, §11.102(b2) rides §11.92(d), Vixy's). Recorded because it is the reason the natural fix for (c) does not work. → **§5.66**.
      * **`Navigator::moveTo` normalises its aim and then multiplies it by 2**, so after any `look_at` the app runs with non-unit vision vectors `[observed: navigator.cpp:353-355, 112-117]`. `SphereGrid::intersect` normalises (safe), `constellation.cpp:180`'s `getPrecEquVision().dot(art_vertex) > 0.9` does not — that test is twice as permissive after a look_at. Pre-existing old-path behaviour, untouched here. → **§5.67**.
