## (b) `harness/screen_record.py` - the reader [observed: the file; measured: the runs below]

**Interface** (importable; the CLI is a thin `main`): `load(path) -> Record(path, header, frames)`, where `header` = {version, B, F, viewport{projector[cx,cy,r], renderer[cx,cy,r], scissor[ox,oy,w,h], annotation}, extra} and each `Frame` = (frame, dt, jd, drawn, fov_old_deg, half_fov_new_rad, bodies {(engine, name): (x, y, size)}, line). `elapsed(rec)` gives the prefix sum of dt. The four table functions return lists of (title, columns, rows); motion / within / compare also return their every-row set for `--all`. `align(ra, rb, mode)` returns `[(i, j or None)]`. `Refused(path, line, why)` is the one refusal (CLI: `screen_record: REFUSED <path>:<line>: <why>` on stderr, exit 1).

**Format readings taken on 11.333 (d)** - each is a point where the spec does not decide on its own. I built on the reading shown, and the supervisor settles each against F160's real record:
- R1 The first line must be exactly `#<tab>screen_record<tab>1`: three fields, nothing after them (P2).
- R2 The `# B` / `# F` column lines are REQUIRED, once each, before any data. Each declared field is read as its first word with a `(...)` suffix cut (`engine(o|n)` -> `engine`), and the first 5 / 6 must be `engine name x y size` / `frame dt_ms jd drawn fov_old_deg half_fov_new_rad`. Any field beyond is ANNOTATION, kept raw. The spec's block shows prose after the columns (`size            x,y: Vulkan axes...`); whether the engine writes that prose, and with spaces or a tab, is not decided. Both forms load: the self-test writes one of each, an extra tab field on `# B` and trailing spaces on `# F`. A mismatch in the declared names REFUSES the record, so a divergence surfaces instead of being absorbed.
- R3 The `# viewport` line is REQUIRED, once: `projector cx cy r renderer cx cy r scissor ox oy w h` = 15 fields, all numbers; fields beyond are annotation. Its absence refuses the record, because `dpos[px]` is derived through the renderer radius. If F160 writes no such line, every record is refused at its first data line ("data line before the header's viewport line").
- R4 Every `#` line precedes the first B / F line (a header line after data is refused). A `#` line with an unknown key is accepted and printed raw by `summary` ("header extra").
- R5 The first F line says 0, and each next F line says previous + 1. The spec restarts the counter at every `state on` and writes one file per `state on`.
- R6 The F line closes its frame: the B lines since the previous F line are that frame's. A record that ends in B lines is refused at the FIRST B line of the unclosed frame. A header-only record (zero frames) loads; the driver requires at least one frame.
- R7 One (engine, name) twice in one frame is refused: a dict would otherwise keep one of the two in silence.
- R8 Numbers are read by Python's `float`, so `nan` / `inf` / `-nan` load as raw values. The tables rank NaN first, motion flags them `NONFINITE`, and the min / max of a set holding a NaN is NaN rather than a random order. A non-number is refused.
- R9 `elapsed[f]` = dt[0] + ... + dt[f], so frame f's own dt is included (frame f is drawn after its dt was consumed). Both runs are read with the same rule. P3's example holds under either convention: inclusive 63 -> 64 (nearest, 1 ms); exclusive 56 = 56.
- R10 Time alignment pairs A's frame i with the B frame of nearest elapsed time. A tie goes to the EARLIER frame. A pair is accepted only if |dt_elapsed| <= max(dt_A[i], dt_B[j]); otherwise A's frame is unpaired and listed. A record whose elapsed is non-finite or decreasing (a NaN or negative dt) refuses `--align time` loud and names `--align frame`.
- R11 The file is decoded as latin-1, byte-lossless, so no decode error can drop a line. The names are ASCII per the field (PREMISES: 90 / 90 `name =` lines match `[A-Za-z0-9_-]`). A CRLF record loads: the `\r` stays in the last field, and `float` strips it.

**Outputs.** Columns carry their units: `[r]` the viewport radius (the record's unit); `[px]` through the header's renderer radius; `[ms]`, `[d]`, `[deg]`, `[rad]`. jd, the fovs, dt and elapsed print at 17 significant digits, the rest at 9.
- `summary`: frames, duration, fps, the min / max of dt, jd and the fovs, frames per drawn tag, bodies and B lines per engine, the viewport. Then ONE row per (engine, body): frames seen, first, last, min / max of x, y, size.
- `motion [--engine o|n] [--k 8] [--top 10] [--all F|-]`, per engine: (i) every body in one row, ordered by max_step / median. A row carries the median step and the max step with the jd / drawn / fovs / dt of its frame, the JUMP count (step > k x median), the absent frames as lossless ranges, and the same rule on |dsize| (SIZE-JUMP). (ii) The position-step and size-step listings: per body the `--top` largest, ordered flag first (NONFINITE, JUMP, none) then ratio; each title says "N of M steps shown".
- `within [--all F|-]`: per body the worst o - n frame with its dx, dy, dpos[r], dpos[px], size_o/size_n, both engines' values, frame, jd, drawn, fovs, dt and elapsed; the min / max size ratio; the counts of frames in both / o-only / n-only. Then every body seen on one side only, with its frames as ranges. A record with no o line says so in a `note` row (a new-pinned run, or after B42).
- `compare <A> <B> [--engine-a n] [--engine-b o] [--align time|frame] [--all F|-]`: the alignment (pairs, A frames left unpaired, B frames no A frame chose, both viewports and whether they are identical), then the same two tables as `within`, with both frames' context and elapsed beside every delta.

## F162 - the screen record's reader, the campaign scene and its driver (`screen_record.py`, `screen_scene.sts`, `screen_drive.py`) - INTENT 11.335 / 11.333 (d) (f), 2026-10-16

**What for.** `body action screen_record` (F160, INTENT 11.333) streams every drawn body, every frame, raw: its screen position in the Vulkan axes and its angular size, both normalized to the viewport radius, for each engine that computed it. The record is never summarised in the engine. These three files are what reads it and what drives the campaign: `screen_record.py` turns raw lines into ordered tables (run against run, within one run, each trajectory's continuity), with the frame, jd, both fovs and the drawn path beside every delta, so a delta can be dug at once; `screen_scene.sts` is the campaign's seven phases; `screen_drive.py` plays them on one pinned path and judges the files.

**Run** - the reader, from anywhere (stdlib only):

    python3 -I screen_record.py summary <rec>
    python3 -I screen_record.py motion  <rec> [--engine o|n] [--k 8] [--top 10] [--all OUT.tsv|-]
    python3 -I screen_record.py within  <rec> [--all OUT.tsv|-]                       # o - n of one old-pinned record
    python3 -I screen_record.py compare <recA> <recB> [--engine-a n] [--engine-b o] [--align time|frame] [--all OUT.tsv|-]
    python3 -I screen_record.py --self-test

The campaign, one pin per call (records in `artifacts/screen/<label>/`):

    cd claude/harness && umask 0002 && bash f124_run.sh ../screen/<label> f125_adapt.py screen_drive.py --pin on|off [--scene FILE]
    python3 -I screen_drive.py <outdir> --pin on|off --dry-run      # the scene file and the sequence, no socket

**Reading the tables.** Units sit in the column names: `[r]` the viewport radius, `[px]` through the header's renderer radius, `[ms]`, `[d]` (jd), `[deg]` / `[rad]` (each engine's own fov unit). Every body is a row, ordered worst first; no row is dropped on its value. motion's step listings are cut by RANK (`--top`) and their title says how many of how many; `--all` writes every row raw (`-` = stdout). `motion`: JUMP = a step > k x that body's median step, and the same rule on |dsize| = SIZE-JUMP; NONFINITE = a NaN / inf raw value; `absent_frames` = the frames a body skipped between its first and last. `compare --align time` pairs each frame of A with the frame of B nearest in elapsed engine time (the prefix sum of `dt_ms`, the frame's own dt included), ties to the earlier, accepted within the larger of the two dts. Unpaired frames are listed, never dropped. Index alignment is `--align frame`.

**The scene.** P0 `rest` (jd 2461233.5, time frozen, fov 180), P1 `fov` (180 -> 20 -> 180 in 3 s each), P2 `track` (Saturn selected and tracked, `zoom auto in` / `out`), P3 `lateral` (`moveto delta_lon 20` / `delta_lat 10`), P4 `altitude` (`moveto alt 20000000`, then the field's `moveto lat default lon default alt default`), P5 `time` (`timerate rate 86400`), P6 `reference` (home planet Moon, then Earth). `@OUT@` is replaced by the absolute outdir. Each `state on` opens its phase file and closes the previous one; `state off` closes the last, then `dual_dump ... end.json` is the sentinel. Total wait: 49 s; commands with no wait between them run in the same frame (F118 above).

**The driver's checks.** Every phase file exists, was written by this run, loads, and holds a frame; every F line's drawn tag is the pin's (on = n, off = o); a new-pinned record has no o line and an old-pinned one both engines; the sentinel parses (`dumpread`) and its `control.drawnPath` is the pin's. It reads the phase files, the sentinel and the poll's bound (waits + 60 s) from the scene, and it refuses (exit 2, nothing sent) a scene it cannot bound, an outdir holding whitespace, or a previous run's phase files. Exit 0 / 1 (a FAIL) / 2 / 3 (the sentinel never came).

**Able to fail, first.** `--self-test` writes a synthetic record pair from the format (two engines, 6 frames: Saturn jumps at frame 3, Mars is missing from n at frame 4, the Moon's size steps at frame 2; a copy at dt 8) and asserts the four functions' rows, P3's alignment (frame 8 at 7 ms meets frame 7 at 8 ms) and seven refused records with their line numbers. Its first run was red on a real defect (empty one-side rows). Five one-line mutants (index alignment, no frame-index check, no JUMP flag, no unclosed-frame check, no engine-tag check) each turn exactly their rows red (INTENT 11.335 (b)).

**Pitfalls, each one measured.** (1) `scedit --check` tests argument keys, flag names / values and set names, NOT command values: `body action dual_dumpx`, `zoom auto inx`, `timerate rate zero` and `moveto lat defaultx` all pass it. Attest such values from the field. (2) The D14 gate reads the code repo's tracked files only; for the harness, census the bytes (`LC_ALL=C /usr/bin/grep -c -P '[\x80-\xff]'`). (3) The format's header lines are REQUIRED by the reader (`# B` / `# F` column names, `# viewport` with 15 fields): a record that lacks them is refused at its first data line, with the line number. (4) A label is used once: the runner removes `*.json` but not `*.tsv`, so the driver refuses an outdir that holds a previous run's phase files.
