    - **(a2) THE SECOND HALF OF THE FIX IS A SECOND INSTANCE OF THE SAME CLASS, and §11.108(e)'s "same fix as the row's" is CORRECTED here.** The row's fix fires once per frame and cannot change what ten descents inside ONE frame do. The descend breach has its own root, in the same sentence: **the reference's eye-frame position is a COPY of the camera's own view matrix, republished once per frame**, and `descend` was reading that copy back (`reference->getObservedPosition()` == `mat.getTranslation()`, and for the reference `body->mat` IS the mat `Camera::update` handed to `dispatchUpdate` — the fold cancels exactly). So the composition became a function, `Camera::viewMat()`, `update()` hands it to the dispatch and `descend` asks it live. I2: the arithmetic is written once and every reader of it is exact by construction rather than by cadence. §11.108(e)'s claim that the row's single fix closes the descend observable is **imprecise, not wrong about the class** — recorded rather than silently repaired.
      **NOT taken, same class, recorded**: the FAR branch of `descend` reads `sel->getObservedPosition()` for the SELECTED body, which the camera cannot derive from its own state. The exact transport exists (`viewMat() · lastDispatchedMat⁻¹ · cached`), and it is not taken because a matrix inverse in the common path perturbs a currently-exact value with float noise and the far case has no measured observable. → §5.32's residual.
    - **(a3) THE SCENE THAT MAKES THE SPIN LEG DISCRIMINATING WAS FOUND BY MEASUREMENT, TWICE WRONG FIRST.** At `look_at altitude +89` the pre-fix binary rotated the full 36°, i.e. the reference was still being updated; at −89 and 100 km altitude it was 90° off the view axis and still inside the cone. The leg now COMPUTES the reference's angle off the view axis and the cone it must clear, from the dump itself, and fails if the scene did not put it outside (90.000° against a 15.342° cone = 15.000 cullHalfFov + 0.342 halfAngularSize) — so a future corpus or fov change cannot silently turn the leg into a null. **The pre-fix null is what proves the regime**: a binary that does not freeze the spin there would fail its own `--prefix` expectation.
    - **(a4) THE ROW'S "persistent-longitude round-trip" IS NOT DRIVABLE, and the reason is a second row.** `longitude ∓= reference->getAxisRotation()` lives in `Camera::setBoundToSurface`, whose only caller is `ssystem_factory.cpp:155`, the config parse — B35's config-only class. What IS drivable, and what that conversion consumes, is the spin value itself: the (a) table's fourth row measures exactly the number the conversion would write. **Also derived and recorded**: a numeric round trip of that pair CLOSES pre-fix (both conversions read one frozen value) and does NOT close post-fix (the surface really spun between them) — so "the round-trip closes" is the DEFECT's signature, not the fix's. The dispatch view's phrasing is corrected here; the §5.32 row's own words ("writes stale spin into PERSISTENT observer longitude") are what the measurement matches.

    - **(b) THE ARTIFACT, and why it is a second one (§3.2).** `~/.spacecrafter/sessions/<name>.ini`, machine-owned and disposable. Content is the product (D9: frozen field, hand-edited, replaced by a paid delivery); a session is a bookmark. Merging them would rewrite paid data at the highest-frequency operation there is, and would make "restore my session" obey the frozen-field rule. The session therefore REFERENCES the files it needs and never copies what is in them, which is what lets a correction that lands in the data underneath a session still reach a session restored on top of it (§9(2)).
      **THE BANNER CARRIES NO DATE AND NO RUN IDENTITY, and that is a requirement**: T4 demands that a save of an unchanged state be byte-identical to the one before it, and a timestamp gives the file no fixed point at all. A machine-owned bookmark must be a function of the state alone `[derived; measured as T4 green at 3426 bytes]`.
      **THE MANIFEST (§3.3)** is one `[system:<name>]` section per loaded system — its name, its file and its READER (composed vs legacy), collected through `ModularBody::forEach` (the global registry, the one place that knows every body there is; the render lists would miss a hidden system, and a hidden system is still loaded content). 18 systems on the shipped tree. At restore the manifest is **CHECKED, not enacted**: a system the session names and the app does not have is REPORTED with the file the session expected, and the rest of the restore proceeds. Enacting it is the §3.3 in-session load/unload twin, and it needs more than the manifest carries (where the system node sits, plus the galactic load surface, which is §5.37's own suspended question) → **the boundary is recorded and the increment is not forced**, per the task's own instruction.

    - **(c) THE FINDING THAT COST THE MOST AND IS WORTH THE MOST: A RESTORE MUST DRIVE THE DUAL SEAM, NOT THE MEMBER.** The first working restore reproduced **every field of `Camera::dumpTrace`** — 25 fields, exact — and the composed screen still differed by **112 184 px>8 against an in-scene A/A floor of 0** `[measured]`.       | — | — | 3 185 residual, (h) |
      §2 row B19 excludes the old Observer/Navigator twin from the file on the stated grounds that *"setters are dual so it follows"* — and that clause only holds **if the restore uses the dual SETTER**. Assigning the camera's members bypasses it silently, and the failure is invisible to every model-layer check: this is §11.52(b)'s verification-height rule met from a new direction (intermediate-layer parity did not compose upward, and the model layer was PERFECT while the dome was wrong). The session now restores the place (`CoreLink::observerMoveTo`), the fov (`zoomTo`) and the sky lock (`Core::setFlagLockSkyPosition`) through their seams, and `Camera::restoreSession` owns only what is new-path-only.
      **A rider found the same way**: `CoreLink::setFov` does NOT stick — the projector keeps an AIM fov that the per-frame mirror re-applies over a bare `setFov`, and the restored scene came back at the launch fov of 180 `[measured]`. `zoomTo(deg, 0)` — the seam `zoom fov X duration 0` itself uses — does. Recorded as a property of that surface, not fixed.
      **A second rider, the same class, cheaper**: the file stores the **fov in DEGREES** and the **altitude in METRES**, i.e. what the seams and the operator's own `moveto`/`zoom` take, rather than the camera's half-angle and centre distance. Storing the half-angle cost a float→double→float round trip through the seam and the value came back one ulp off — enough to lose T4's byte-identity (3425 vs 3424 bytes, measured).     - **(d) WHAT THE FILE CARRIES, by §2 row.** Group A: `jday`, `time_speed`, `paused` (A1–A3; A4/A5 ride D36/D32 and are out). Group B: reference, tracked, free_mode, bound_to_surface, mount, longitude, latitude, altitude, position, alt, az, fov, sky_locked, **sky_rot** (the held matrix — B9 calls it state and nothing else here derives it), view_offset and its ARMED latch (B10, D32's first named carve-out: the latch is a condition and is saved, its ramp is a motion and snaps). Group C: `selected`, `track_object` (C1/C5). Group G: the manifest (G1).
      **D32 IN THE SAVE, not in the loader**: a move in flight is written where it was GOING (`position += deltaPosition·moveDuration`, closed form, no assumption about frame timing); a view-smoothing plan is written at `rotateAbout(viewFrom, viewAxis, viewAngle)` — `advanceView`'s own exact landing; a zoom is written at `dstHalfFov`. `restoreSession` clears every plan FIRST, because a plan that survived a restore would immediately start moving away from what was just restored, and the second restore would then land somewhere else — which is exactly what D33's idempotence forbids.
      **ORDER IS THE CONTRACT, and it was measured**: time → warp → place → fov → sky lock → the camera's own members → selection. Time comes first because the warp computes a compensation from the two bodies' positions AT THE CURRENT DATE; with the warp first, the restored scene came back rolled, because `recoverParams` had run at the launch date. The sky lock precedes `restoreSession` because engaging it CAPTURES the current view, and `restoreSession` then overwrites that capture with the matrix the session actually held.

    - **(f) THE TRIGGER (§3.5), and its spelling is a VETO POINT.** `session action save|load [filename <name>]` — one registration serving all of §11.55(h)'s channels, the `<noun> action <verb>` grammar the surface already uses, and a sibling of `body action save` (§11.121(e)) and `camera action save` rather than a new grammar branch. **B28 protocol, F7's `follow_rotation` and F15's `body action save` are the precedents**: it is landed and live, and reversing it is one `else if`. `filename` is optional on both legs (absent = `session`). The refusals live where the artifact's placement is owned: a path is refused with what fired, why and what to fix (§2(f)), and a session is written in `sessions/` and nowhere else — the frozen legacy corpus is unreachable by construction (D35 / §2.0 D13). A file whose `[session] format` this build does not read is **refused whole** rather than half-applied (§9(1)).
      **The D8 USE-SITE (§6.1)** is honoured at this slice's own use sites: every body the session names (reference, tracked, selection) is brought to the current date by `useNow` before it is read. **Scope stated rather than implied**: this slice names three bodies; the obligation §6.1 calls *"the first consumer that touches EVERY body"* arrives with the ledger, which walks the tree.
      **Frame boundary and off-thread I/O**: the command executes on the main loop thread between frames, which is not the draw thread (the draw runs on `RenderChain`'s worker), and `ModularSystemFormat::write` is the atomic sibling-temp-then-rename §11.52(a) clauses 1–2 already implement, so a partially written session is unobservable. Nothing new was built for this; the property was verified at source rather than assumed.
