# INTENT §11.119

119. **B31 SLICE 1 — A FILE THAT GOES THROUGH THE WRITER COMES BACK WHOLE (2026-07-30, Opus 5 executor dispatched by Claude Fable 5, task F13; code `9f60d3a1` the layer + `99685172` the parse simplification; harness `a8a198f` the gate + this entry).** §11.66(b)'s preservation contract is implemented at the layer that owns it, per `b31-design.md` §5.2/§5.3 — the second step of §11.110's own sequencing (§5.39 unification → **writer rework** → persistent-body serialization → session file → ledger). Nothing user-visible changes on this install: the layer has no live mutation caller yet, and the one live writer (the composed twin) emits **byte-identical** output to the pre-F13 binary's on all 18 twins. Frozen data md5 in == out around every launch of this wave (`config.ini` `03fbee59`, `ssystem.ini` `545a51ef`, `galactic.ini` `27d581f0`, `anchor.ini` `9c7def9b`) — D35/§11.113(n) and §2.0 D13 asserted, not assumed.

    - **(a) THE STRUCTURE: a `Section` is an ordered LINE LIST, and the key index is DERIVED from it (I2).** `ModularSystemFormat::Section` stops being `{header, std::map}` — a map cannot hold what it does not understand, and everything a map drops is somebody's work. `parse` keeps EVERY input line in order, classified by the one grammar (`tools/ini_line.hpp`) into COMMENT / BLANK / KEY / RAW, where RAW is "neither comment nor entry": carried verbatim, never interpreted, never dropped. `write` emits them back. The `index` (key → its effective line, last occurrence winning as every loader in this tree already resolves a repeated key) is rebuilt from the lines and is never edited beside them, so the two cannot drift `[observed: ModularSystemFormat.hpp:83-175, ModularSystemFormat.cpp:110-135]`.
      Mutation rules, each with the requirement it serves:
      * **`set` rewrites a value INSIDE its own line** — the new text is spliced into the value's span, so the key as the author spelled it, the blanks around the `=` and any trailing comment stay byte-for-byte `[observed: ModularSystemFormat.cpp:158-190]`. This is also what makes the §11.109(h2) whitespace case round-trip through the *rewrite* path — incidentally, exactly as §5.2's own note says, and **without deciding the format-semantics question, which stays SUSPENDED**.
      * **a new key lands after its section's last DECLARATION**, not after the blank line or the trailing comment that ends the section — a key placed there reads as belonging to whatever comes next `[measured: leg "new key", the appended line sits between `annotated_key = 42` and the section's blank line]`.
      * **`remove` COMMENTS THE KEY OUT with its reason above it, never deletes** (D9: authored text an engine deletes is gone). The retired line keeps its own text behind a `#`, and the reason lines are ordinary comments — deliberately NOT machine-marked, because the marker namespace is regenerated on every write and a marked removal record would delete itself on the next one `[derived; the failure it avoids is data destruction]`.
      * **an unrepresentable value is REFUSED with a §2(f) diagnostic and changes nothing.** The test is a round-trip through the grammar itself rather than a character blacklist (I6: the class, not the instance) — plus the one thing a round-trip cannot see, a line terminator inside the inserted text (see (g)).
      * `IniLine::read` now reports the value's **span** in the raw line and takes the line by const reference. The only thing that knows where a value sits is the grammar; asking the writer to re-find the `=` would be the second copy of the arithmetic §11.115(b) created that header to end `[observed: ini_line.hpp:58-72, 100-149]`.

    - **(b) §5.3's PRECONDITION RE-MEASURED AT HEAD, NOT INHERITED — and it is already met for exactly the files it must be met for.** §5.3 requires that the loader own the parse the writer round-trips, or an annotation lands next to the wrong datum. Measured at HEAD before writing any code:
      | reader | parse it uses | may its file be written? |
      |---|---|---|
      | `ModularSystem::loadSystem` (legacy bodies) | `IniLine::read` directly `[observed: ModularSystem.cpp:1402]` | **NO** — D35: legacy files read-only forever |
      | `ModularSystem::loadComposedSystem` | `ModularSystemFormat::parse` `[observed: ModularSystem.cpp:1437]` | yes (composed) |
      | `ModularSystem::generateComposedTwin` | `ModularSystemFormat::parse` `[observed: ModularSystem.cpp:1546]` | writes the twin `[:1654]` |
      So the half of §5.3 that was a precondition — *the loader and the writer must agree which line a key came from* — holds by construction on every file this layer may write, because their loader IS the format parser. F10 (§11.115(b)(d)) closed the other half, the key-level desync, by putting all four readers on one grammar. **What remains is NOT a parse question**: `loadComposedSystem` discards its parsed sections at the end of the load, so today there is no object for a loader's annotation to travel on. Retaining them belongs to the first slice that has a write trigger (persistent-body serialization / the session file). Recorded, not built — see (i).

    - **(c) THE ANNOTATION HALF, and why it is idempotent by construction.** Only the loader knows a datum is wrong, which states are valid, what was applied instead and what would fix it, so `Section::annotate(key, reason, text)` is the loader's channel and the writer merely PLACES the result — **above** the datum, because the legacy reader takes a value as the rest of its line and a trailing annotation would be swallowed into it (silently for a number, destructively for a name or a texture path). Keyed `(key, reason)`: the same verdict said twice is ONE annotation carrying the later text.
      **The `#!sc:` marker is a machine-owned namespace, and that is the whole idempotence mechanism**: a write DROPS every marked line it finds and re-emits what was diagnosed THIS time. Consequences, both wanted: a second rewrite with the same diagnosis is byte-identical (T9), and a diagnosis nobody reached this load does not outlive itself (D12: an annotation is *forbidden* where nothing acted). Human comments — any comment that is not marked — are never touched `[measured: legs "annotation", "T9 idempotence", "stale annotation", "annotation replace"]`.
      **Section identity is structural, not by name.** §5.3 says the annotation set is keyed `(section, key, reason)`; the annotations live ON the Section object the loader read them from, which realizes the `section` component without a header-text match — headers are decorative and may repeat, and a name match would put a diagnosis in the wrong section the first time two sections shared a header `[derived: I2/I4, no user-visible semantics involved]`.

    - **(d) THE GATE: `claude/harness/b31_writeback.py` + `b31_format/format_gate.cpp`, twelve legs, GREEN, discriminating three ways.** The instrument compiles the PRODUCT sources (`ModularSystemFormat.cpp`, `tools/log.cpp`) straight out of the tree and drives them — a Python reimplementation of the parser would only ever test the copy. The corpus (27 lines / 654 bytes) exists to be destroyed by a writer that does not preserve: a two-line banner belonging to no section, blank lines, `radius  =  1234.5` and `  indented_key=squeezed` (irregular spacing), an empty value, an ISO-8859 value, `orbit_LongOfPericenter 95.58754` (the shipped `[Sedna]` malformed class, §5.39), an unknown key, a duplicate key, `orbit_visualization_period = 0.9424218 #### <0xE0> affiner source stellarium` (the shipped `[mimas]` trailing-comment class, §11.109(e)), a human comment attached to a datum, a header with a trailing comment, a `= value with no key`, a section that declares nothing, a CRLF-terminated section, and **no final newline**.
      | leg | result |
      |---|---|
      | round-trip | **byte-identical**, 654 → 654 |
      | malformed-is-not-a-key | neither malformed line became a key; both survive verbatim |
      | value change | **exactly 2 lines moved, each only in its value**: `radius  =  9999` (spacing kept) and the `[mimas]` line keeping its high-byte comment tail |
      | new key | +1 line, at the section's last declaration; nothing else moved |
      | removal | `#unknown_key = …` survives with a reason line above it; the key no longer parses; nothing else moved |
      | annotation | 3 marked lines directly ABOVE the datum, the human comment above them untouched, nothing else changed |
      | **T9 idempotence** | second rewrite with the same diagnosis **byte-identical** |
      | stale annotation | the marked line goes, the human comment and the datum stay |
      | annotation replace | same `(key, reason)` twice ⇒ ONE line with the later text; a diagnosis about an absent key lands at the section's end |
      | representability | 3 refusals (comment character, newline, outer blanks), each with a §2(f) message naming the key and the fix, file untouched |
      | CRLF | a value rewritten in a CRLF section keeps its own `\r`; exactly one line moves |
      | last line | a file that ended without a newline gets one back when something is appended after its last line |
      **Discrimination 1 — the writer this slice replaced**, built from `f1151c63` and run on the same corpus: **297 bytes out for 654 in, 14 of 27 lines lost** `[measured]`. A gate both writers pass is testing nothing.
      **Discrimination 2 — the naive annotator** (insert above the datum, never look for an earlier one), implemented in the gate as the counterfactual: it **grows the file by 3 lines per rewrite** and FAILS the T9 leg `[measured]`.
      **Discrimination 3** — every leg asserts what must NOT move as well as what must: a value change that touches a second line fails even when the value is right.

    - **(e) THE SHIPPED CORPUS ITSELF ROUND-TRIPS, ON COPIES — never the originals (D35).** `ssystem.ini` (2518 lines / **59105 bytes**), `galactic.ini` (**2177 bytes**) and the generated `SolarSystem.ini.disabled` (**77488 bytes**) each come back **byte-identical** through the layer `[measured, copies in the scratchpad; the real files' md5 unchanged before and after]`. This is the §11.66(b) claim on the real product data rather than on a constructed corpus.

    - **(f) THE ONE LIVE WRITER IS BYTE-STABLE ACROSS THE REWORK.** The 18 machine-owned twins were deleted, regenerated by a fresh launch of the F13 binary, and compared against the ones the pre-F13 binary (`f1151c63`) wrote: **18/18 byte-identical**, set identical, `SolarSystem.ini.disabled` md5 `978c3a85…` on both sides `[measured, twice — once per code checkpoint]`. That is what makes the twin generator's restructuring (it now builds each section's params as one map and hands it to `Section::fromParams`) a refactor rather than a change: key order, spacing, the blank line before each header and the banner are all reproduced.

    - **(g) THE GATE CAUGHT A DEFECT IN THIS IMPLEMENTATION, which is the reason it exists.** The first representability test was a round-trip through the grammar alone: build the candidate line, re-read it, compare. A value carrying a **newline** passes that test — the grammar is handed one line at a time, so it reads the text back intact and the damage only appears at emission, where the line becomes two and the second is something nobody asked for. Measured as an unexpected exit 0 on the `two\nlines` case; fixed by testing the INSERTED text for a line terminator (and only the inserted text — a CRLF file's own `\r` must keep working, which the CRLF leg now holds down) `[observed: ModularSystemFormat.cpp:47-58]`.

    - **(h) COST, on the load-time denominator — D11's 1 ms/frame does not apply, nothing in the frame loop changed.** On the shipped `ssystem.ini` (59105 bytes / 2518 lines), 100 runs each, process baseline subtracted: **parse 5.19 ms**, **parse+write 6.75 ms**; the pre-rework parse+write was **2.14 ms** `[measured]`. The +4.6 ms is the line storage the preservation contract exists to pay for (2518 lines retained instead of ~2300 map entries), spent once per system load. A first version cost 7.16 ms because `parse` asked the grammar what a line was and then had the Section ask again; that redundancy is gone (`99685172`), which is also the simpler shape. Further reduction is available and NOT taken (D10: the potential is not here) — a KEY line stores `key`/`value` as copies of substrings of its own `raw`, and spans would remove two allocations per entry.

    - **(i) WHAT THIS SLICE DELIBERATELY DOES NOT DO, with the reason.**
      * **No live loader produces an annotation yet, and no composed file is rewritten at load.** The mechanism is complete and gate-exercised, but wiring a producer requires retaining the parsed sections past the load, and *making a load rewrite the user's composed file* is a user-visible semantic nobody has decided. → the next slice's first step, with the write trigger it needs. **Not suspended for Vixy: it is sequencing, not a decision** — the trigger the design already names (an explicit session/system save, D33) supplies it.
      * The session file (§3.2), the override ledger (§2 group D) and persistent-body serialization (§4.1) are later slices, untouched.
      * §5.41 / §5.42 (`camera action save`, `configuration action save`) are untouched: they re-express on the session serializer, as B31's own design says.
      * **§11.109(h2) stays SUSPENDED.** The rewrite path now round-trips a whitespace-bearing key incidentally (it never re-spells the line), which is §5.2's own note; the format-semantics question it raises is untouched and undecided.

    - **(j) OUT-OF-SCOPE FINDS, recorded not fixed.**
      * **`cLog::write` aborts the process when no log file has ever been opened**: it falls back to `logFile.at(LOG_FILE::INTERNAL)` unconditionally, and `std::map::at` throws `std::out_of_range` on a logger nobody called `openLog` on `[observed: log.cpp:150-156]`. **Measured** (SIGABRT, `terminate called after throwing an instance of 'std::out_of_range' / what(): map::at`) the first time the gate tool hit a §2(f) refusal path. **Not reachable in the app at HEAD**: the only code between `cLog::get()` and the five `openLog` calls is directory checking, which does not log `[observed: main.cpp:190-213]`; `CallSystem::checkIniFiles`, which does log `[call_system.cpp:93]`, runs at `main.cpp:225`, after. It is a trap for the next contributor who logs earlier, not a live defect — hence recorded here rather than as a §5 row.
      * **Mixed line terminators**: a key appended into a CRLF-terminated section is emitted with LF (`body = Alpha\nadded = yes`) `[measured, leg "last line"]`. Grammar-legal (`\r` is a blank on both sides of the family's readers) and inert for every consumer in this tree; the shipped corpus is LF throughout. Not fixed: matching the neighbouring line's terminator is a guess about what the author wants, and no file in the field poses the question.
