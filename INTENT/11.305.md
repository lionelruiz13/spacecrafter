    - **(b) THE STRUCTURE READ FROM (a)** [derived, each line veto-open]. One REGISTRY, the responsibility anchor of every binding (where the key event, the running script's identity and the chain meet). Per (key, event ∈ {press, release}) a CHAIN: entries `(script-name-or-'-', scope, owner)` where owner = the script that registered it (`script` scope) or nothing. Resolution at an event: the most recently registered live entry; none → the DEFAULT, the handler as written today, never stored. Registration: `global` (scope absent) REPLACES the chain with itself — nothing below it can return, by his reason (a global cannot be reverted by a trigger, so what it covers is unreachable forever; only `-` reinstates the default, deterministic hence unstored); `script` pushes an entry that leaves when its owner script ends — wherever it sits in the chain (a `once` registered after it may be above it); `once` pushes an entry that leaves when it triggers, the chain's next live entry taking over (his example: global → script → once, the script ends first, the once triggers → the global). `-` is a name like any other: scopable, so a script can shield an event (`release - scope script`) while binding the other. `*` = every key, given with `press - release -` to reinstate every default. The key omitted = the key whose binding is running this script (valid only there; elsewhere an error, like a missing name after `press` / `release`). Press and release never read each other's chain.
