    - **(f) THE FIND — a heap-use-after-free on EVERY shutdown, on SHIPPED data, no scene composed [measured, `b7h3_asan_k0/plain_001_frcmd.log`; attributed at source]**: the very first ASan cycle fired. With no composed scene at all (K = 0): **1 × heap-use-after-free + 5 × new-delete-type-mismatch**, and ASan's fatal exit (rc=1) *killed the shutdown partway through*.
      **READ of size 8** at `EnvironmentManager::notifyBodyDestroyed` — `EnvironmentManager.cpp:28`, `auto &chain = instance->activeChain;` — called from `ModularBody::~ModularBody` (`ModularBody.cpp:237`), nested through `clearChildren()` / `~ModularSystem` up to `~SSystemFactory`. **Freed by** `SSystemFactory::~SSystemFactory` (`ssystem_factory.cpp:148`). **Allocated by** `SSystemFactory::wireEnvironment` (`ssystem_factory.cpp:837`, the single call site, `core.cpp:166`).
      **Mechanism**: `EnvironmentManager::instance` is a static non-owning back-reference set in the constructor and **never cleared**. `SSystemFactory` destroys its `environment` member *before* the modular system whose bodies do the notifying, so every body destroyed during shutdown ran `chain.erase(std::remove(...))` — a **write into freed memory** — against a `std::vector` that no longer existed. The reader's own guard, `if (!instance) return;`, already states the invariant ("no manager ⇒ nothing to notify") and the header's declaration comment already states the I5 contract; nothing ever established either at the end of the lifetime. **This is the B7/§11.15d class by construction** — a teardown write into freed memory, on every single shutdown — and it is invisible natively because the freed block usually still holds plausible pointers, which is exactly why 266 native teardowns across two hunts never saw it.

    - **(g) Fix landed, with a both-ways discriminating check [code `1e44b639`]**: `~EnvironmentManager` clears the registration, guarded on `instance == this` so a manager replaced by a newer one (the ctor runs before the old dtor in a `make_unique` reassignment) cannot clear its successor's — `wireEnvironment` is called once today, so the guard is defensive, not load-bearing. **RED → GREEN, three teardown entries** (shutdown command, SIGINT with a reload in flight, old path): heap-use-after-free **1 → 0, 0, 0**, and the shutdown that ASan used to kill at rc=1 now **runs to completion at rc=0**. Judged decision-free under the F8 stop boundary: no user-visible semantics (it executes after the last frame), no design choice (the ownership pattern already fixes what the destructor must do), one line.

    - **(h) NEW §5.51, recorded NOT fixed — `BodyModule` has no virtual destructor [measured + source]**: the same first ASan cycle reported `new-delete-type-mismatch` — *allocated 200 bytes, deallocated 16*. `ModularBody::components` is a `std::vector<std::unique_ptr<BodyModule>>` (`ModularBody.hpp:1671`) destroyed at `ModularBody.cpp:227`, and `class BodyModule` (`BodyModule.hpp:149`) declares a pure-virtual `draw` and no destructor at all ⇒ the implicit one is non-virtual ⇒ deleting **13 subclasses** through the base is UB and **no module destructor has ever run**. Post-fix, with the shutdown no longer cut short, one teardown reports **373** of them (**746** on a `qda` cycle, the reload doubling it). Not fixed here on purpose: the one-line fix would make 13 destructors run for the first time ever, releasing Vulkan resources in an order nothing has exercised — that blast radius needs its own dispatch and its own regression battery, which is larger than a hunt's stop boundary allows.
