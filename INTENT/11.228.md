    - **(b) THE FIX, AND WHY IT COMPARES FIVE FIELDS AND NOT THREE.** `git filter-branch` rebuilds EVERY commit in its range: its default commit filter is `git commit-tree "$@"`, which mints a new object from tree + parents + the ident environment + the filtered message. An unselected UNSIGNED commit comes back byte-identical, so its sha does not move and the rebuild is invisible — which is why nobody noticed for a year. A SIGNED one does not, because `commit-tree` cannot write a `gpgsig` header. `--commit-filter` replaces that default with a command that receives the filtered message on stdin, `<tree> -p <mapped parent>…` in `$@`, `$GIT_COMMIT` = the original id and the ident environment as the env-filter left it, and whose STDOUT is taken as the new commit id — **including an id that already exists** [observed: `/usr/lib/git-core/git-filter-branch:480-482`, the filter's stdout is written straight into `../map/$commit`]. So "leave this commit alone" is one line: `printf '%s' "$GIT_COMMIT"`. The new mode sits beside `--emit-env` and `--msg-filter` in the same self-invocation pattern (`$SELF` absolute), reads the original object ONCE with `git cat-file commit`, and emits the original id when ALL FIVE of tree, parents (in order), author ident, committer ident and message (byte-exact) are unchanged; otherwise `git commit-tree "$@"` with the message on stdin, exactly as before. **Five and not the mandate's three**, and the argument is §11.227(b)'s own sentence — *"a GPG signature signs the whole commit object — tree, parents, author, committer, message"*: comparing three of the five would let a `--tree-filter` or a committer rewrite through, and emitting the original id for a commit that is NOT the original produces a silently WRONG history, which is worse than the silently shortened one being fixed. Today the two extra fields are inert BY CONSTRUCTION and that is measured, not assumed: with no tree/index/subdirectory filter passed, filter-branch hands over `$commit^{tree}` verbatim [observed: `git-filter-branch:373-380` sets `need_index` empty, `:487-491` takes `git rev-parse "$commit^{tree}"`], and this script's env-filter exports `GIT_AUTHOR_NAME` and nothing else (`:415-424`). *"A validation belongs on the value, not on the caller's promise to have validated it"* is the file's own line (`:421`), applied to itself.
