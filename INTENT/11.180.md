    - **(d) WHY SO FEW ARE STALE, AND IT IS THE RESULT WORTH KEEPING: the row id is
      OVERLOADED.** A §13 id names two different things at once —
      * a **QUEUE**, work the row will do, which goes stale the moment the row closes,
        delivers or delegates; and
      * an **ARTIFACT** the row BUILT, which outlives it — a code seam, a protocol, a defect
        class, a precedent.

      The sharpest specimen is **B28**. The row is *"Loader frame declaration + conversion"*,
      **fully closed 2026-07-23** and archived. Three live §5 rows speak of it in the present
      tense (§5.70 *"B28 owns command spellings"*, §5.77 *"a new interface, B28-adjacent"*,
      §5.82 *"B28 also forbids minting around it"*), which reads as a dead routing — until one
      measures the corpus: **"the B28 protocol"** is live vocabulary for *new product surface
      needs a spelling sign-off*, used at §11.78, §11.111, §11.121, §11.128, §11.150, §11.155,
      §11.156 — and **by the owner himself on 2026-08-26** (§11.154(b): *"ONE GATE: B28 sign-off
      on the new-format scaling key"*), five weeks after the row shut, with the gate then
      DISCHARGED at §11.155(a). Same shape at **B16** (§5.104 *"rides B16's seam"* — the seam is
      `body action reload`, which is code and exists) and at **B15/B19/B32**, whose ids are used
