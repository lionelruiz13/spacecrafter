# INTENT §11.121

121. **B31 SLICE 2 — A BODY A SCRIPT PUSHED CAN BE WRITTEN BACK AS AUTHORED DATA, AND A LOADER'S DIAGNOSIS TRAVELS WITH THE DATUM (2026-07-30, Opus 5 executor dispatched by Claude Fable 5, task F15; code `5a8881ff`; harness `121b238` the gate + `c676cf3` the screen leg + this entry).** The third step of §11.110's own sequencing (§5.39 unification ✓ → writer rework ✓ §11.119 → **persistent-body serialization** → session file → ledger). The live tree becomes a serialization source: `body action save [filename <name>]` walks this system's subtree and writes one declaration per body that carries one, through the F13 line-preserving writer. **B25's remaining half closes with it** (*"script-triggered on-the-fly system save … needs the live-tree serialization source"*), and §11.119(b)(i)'s annotation mechanism — complete and producer-less since slice 1 — acquires its producers and the explicit write trigger that D33 says is the only thing allowed to write them. Nothing changes on a shipped install that does not issue the command: the 18 machine-owned twins are **byte-identical** to the pre-F15 binary's, and the frozen data md5s are unchanged around all ~25 launches of this wave (`config.ini` `03fbee59`, `ssystem.ini` `545a51ef`, `galactic.ini` `27d581f0`, `anchor.ini` `9c7def9b`).

    - **(a) THE SOURCE: a body keeps what declared it, and that is the whole structure (b31-design §4.1).** `ModularBody::declaredParams` is the parameter map the body was loaded from, snapshot at `loadBody`'s FIRST statement — before the loader's own `operator[]` reads insert an empty entry for every absent key (§11.103(b)'s trap, met from the other side: a snapshot taken one line later would author a dozen keys nobody wrote into the user's file) `[observed: ModularSystem.cpp:1017-1023]`. **Why the body and not the file**: a save must reproduce the DECLARATION, not the derived state — `rot_periode` is consumed into a rotation rate, `tex_map` into a loaded texture, the orbit keys into an `Orbit` object, and none of those come back out. A body declared by a file has its file to re-read (that is exactly what `generateComposedTwin` does); a body a script pushed has **no file**, and the map that created it is the only record of it there will ever be. That is `saveOrbit()`'s own rule (DATA KEYS, never derived state) applied to the whole declaration instead of one orbit `[b31-design §4.1]`.
      **EMPTY is load-bearing**: a body no data declared has nothing to write, and the save skips it. Measured on the shipped tree: **2 of the 93 bodies in SolarSystem's subtree** are engine-minted — `baryEarthMoon` (the binary-orbit barycentre; not a section of `ssystem.ini`, and the twin does not declare it either) and `orbit_autour_lune` (an `anchor.ini` camera anchor parented to the Moon) `[measured, the save's own log line: "91 declarations added, 0 already declared, 2 engine-owned bodies skipped"]`. Writing those would make the next launch load them twice — once from the file, once from the code that mints them — and would turn a camera anchor into authored content, which F7/R3 explicitly decided against (anchors are camera state, no cross-session persistence).

    - **(b) THE WALK, and the three membership rules it encodes.** `collectContentBodies` is a pre-order walk of this system's subtree `[observed: ModularSystem.cpp:1795-1819]`. **Parents first**, because a declaration may only name a body declared before it (the `findBody` forward-reference rule the composed format inherits) — the order is a correctness condition, not a preference. **Hidden bodies are walked like any other**: a hidden body is declared data (`[Goldilocks_Zone]` ships `hidden = true`) and its `hidden` key travels in its own declaration, so it comes back hidden; since B39 (§11.117) hidden bodies are OUT of `sortedSystemBodies`, so a walk of the sorted list would have silently dropped them — the child lists are the authority here. **A nested system node ends the walk**: its content is declared by its own file and the node itself by whoever created the system (galactic.ini, SSystemFactory). Measured: of the 121 bodies in the live tree, the save considers 93 and writes 91; the 28 it never reaches are the 18 galactic system nodes + MilkyWay + Universe + SolarSystem itself + 7 anchor bodies outside this subtree `[measured]`.

    - **(c) ONE EMITTER, TWO CALLERS (I2) — and the twin's bytes prove the refactor.** `composedNodeParams` + `appendWholeDeclaration` are the twin's per-body block, lifted out and parameterized by the declaration record: the twin passes the legacy section it just parsed, the save passes `body->declaredParams` `[observed: ModularSystem.cpp:1688-1793]`. Both emit the same node section (declared keys verbatim, `bound_to_surface` → `relation = grounded`, and the capability keys the LIVE body carries that a composed load would not otherwise reproduce — `sidereal_time`, `shadow_color`, `surface_model`, `trail_length`, `light_source`, `primary`, `shadow_exempt`), then `compose = explicit` and one BodyModule declaration per module.
      **Which module list, and why not always the live one** `[derived, and the reason is a hazard]`: for a body whose declaration DEDUCES its modules the list is re-derived by `deduceBodyModuleList`, because deduction preserves their ORDER — and the order is semantic (a routing list holds modules in record order, and that is the draw order: the atmosphere shell draws after the disc, §11.19). The live slot list is ordered by global slot id and would silently re-order them. A body whose modules did NOT come from deduction (`compose = explicit`) has no such derivation and its live set is then the only honest answer. Emitting the live set unconditionally was the first shape of this function and was retired for that reason.
      **Result, measured**: the 18 twins are byte-identical to the pre-F15 binary's (md5-compared, `SolarSystem.ini.disabled` `978c3a85…` — the value §11.119(f) recorded), **18/18, twice** (after each code checkpoint).

    - **(d) A FILE THAT EXISTS IS EDITED, NEVER REBUILT — and what this slice deliberately does not edit.** The base of a save is, in order of authority: (1) the sections this system was LOADED from, when the save targets that same file — they are that file's content AND they carry the loader's annotations; (2) a parse of the target, when it exists but is not our source; (3) nothing, for a target that does not exist yet, which is then built whole like the twin `[observed: ModularSystem.cpp:1821-1893]`. So §11.66(b)'s preservation contract, implemented at the layer in slice 1, now applies on the LIVE path.
      **What is added is only what is missing**: a declaration for every live body the file does not declare (matched by the `name` key of a section that binds no `body`). **A declaration the file already carries is NOT edited**, and that is a boundary rather than an omission: a value an operator changed at runtime belongs to the session ledger (b31-design §2 group D, a later slice), and silently rewriting an author's line here would pre-empt a decision this slice does not own. In this slice nothing else CAN have changed, so the rule costs nothing and forecloses nothing.

    - **(e) THE TRIGGER, and where its refusals live.** `body action save [filename <name>]` — the system-scope sibling of `body action reload`, which already occupies that slot (`reload` re-reads this system's file, `save` writes it), one registration serving all of §11.55(h)'s command channels `[observed: app_command_interface.cpp:3585-3599]`. Absent `filename` = this system's own composed file, i.e. §11.51(a)'s *"targeting without the .disabled"*; a name = the same directory, `.ini` appended when it carries no extension (`filename Mars` writes a file something will open, rather than one nothing ever will).
      **The refusals are at the SSystemFactory seam because that is the level that owns file placement and the .ini/.ini.disabled ownership split** `[observed: ssystem_factory.cpp:792-835]`: a path separator is refused (everything outside `modularSystem/` includes the frozen legacy corpus — D35, §2.0 D13) and so is the machine-owned `.disabled` name (the next legacy load would overwrite the save without a word). Both say what fired, why, and what to do (§2(f)); both were measured to write nothing.
      **SPELLING IS A VETO POINT** (B28 protocol, F7's `follow_rotation` precedent): `body action save [filename <name>]` is landed and live, and reversing it is one `else if` — recorded here rather than suspended, per the task's own instruction.

    - **(f) THE ANNOTATION HALF: one verdict, two channels, written only when asked.** `diagnose(origin, key, reason, text, severity)` writes the sentence to the log AND, when the datum sits in a file this engine may write, annotates that datum's section with it `[observed: ModularSystem.cpp:120-132]`. `origin` is the `ModularSystemFormat::Section` the declaration came from — non-null only on a composed load, so a legacy file (READ-ONLY forever) and a script's parameter map produce no annotation **by construction**, not by a guard. `loadComposedSystem` now KEEPS its parsed sections (`loadedSections`), which is what gives an annotation something to travel on and simultaneously makes the save's base the file's own content; `loadSystem` CLEARS them, so a legacy file's layout can never become a write base.
      Fourteen call sites wired, every one a §2(f)/D12 diagnostic that loadBody / loadComposedSystem / loadDeclaredModule emit about a datum in a writable section: the three retired-`type`-capability warnings (annotating `type`, keyed by the capability), the light_source/shadow_exempt conflict, an invalid `relation` (node and module), `relation` contradicting `bound_to_surface`, an invalid `compose`, an invalid module family, an unresolvable `body`, and the 24 h rotation default. **NOT wired, recorded**: the static value parsers (`parseSurfaceModel`, `parseSiderealTimeModel`, `parseCapabilityFlag`, `parseAtmosphereModel`, `resolveRotationFrame`) have no section in hand; giving them one is a defaulted parameter on five signatures, mechanical, and belongs with whichever slice next touches them.
      **A load still never writes.** D33 decided against a rewrite at load (§11.113(l)) — it is decided-against, not undecided — and the gate measures it: a launch on an annotated corpus leaves the file **byte-identical**.

    - **(h) THE SCREEN LEG, and its residual attributed rather than tolerated.** The model layer does not compose upward on its own, so the restored body is also measured where a viewer would see it. The comparison is necessarily cross-launch, and a cross-launch pair of this scene differs by a few hundred pixels for reasons unrelated to the body (B30, §11.53(e); **measured here as 267 px** on the rover-free scene). So the floor is not the criterion: the frame is split at the body's own **footprint**, measured WITHIN one launch (pre-push shot vs post-push shot: **8462 px**, no launch noise in it at all). Live-vs-restored then differs by **118 px inside that footprint (1.39 %)**, and — the part that makes it an attribution rather than a tolerance — **exactly 1 of those 118 px survives a 2 px erosion** (0.01 % of the 7077 px interior). The leg's own counterfactual runs on the same frames: compared against a rover-free frame, the same measurement reports **8308/8462 px (98 %)** `[measured]`.

    - **(j) OUT-OF-SCOPE FINDS, recorded not fixed.**
      * **NEW §5.50 — `body action load … coord_func surface_point` KILLS THE APP.** Measured (the app died mid-session, socket broken, no error line after the load) while probing a screen scene. Mechanism, at source and not guessed: the OLD path's orbit creator does not know the new path's `surface_point` family, logs *"something went wrong when creating orbit"* — **and carries on with `orb == nullptr`** `[observed: protosystem.cpp:612-622]`, building a Body around it. F15 does not touch that file; the trigger is a value only the new path understands, reachable from any script. Attributed by source + log, NOT by a counterfactual binary (no pre-F15 binary was kept — recorded as the weaker evidence it is).
      * **The command layer authors keys into the body it pushes.** A script-pushed body's declaration carries `action = load`, `path = scripts/`, `tex_ring = scripts/` and three empty keys (`mode`, `skin_tex`, `skin_use`), because `commandBody` reads those slots out of its own `args` map through `operator[]` before handing it to the loaders `[observed: app_command_interface.cpp:3523,3545,3555,3564-3566; measured in the saved section]`. They are inert on reload (measured: the T6 comparison is field-for-field equal) and one of them is load-bearing (`path` is what makes a script's textures resolve after the restore, `StarLoader.cpp:36`), so the save writes the declaration as it was made rather than filtering by name — filtering command words at the writer would be exactly the name-sniff I4 retires. The map's shape is the command layer's to fix if anyone wants it clean.
      * **`b40_parity.py` passed vacuously**: run without a `<tag>=<binary>` argument it launched nothing and printed `OK`, exit 0 — the §11.101(g) class, met in this task's own battery run. **FIXED at the instrument** (usage + exit 2, harness `c676cf3`), because it was producing my evidence.
      * **A foreign launch of the app was observed on this host** at 21:49 today, between this executor's build and its first measurement (twin mtimes + log timestamps, no process of mine). Harmless here — the twins it wrote match the F13-recorded md5 exactly, and every measurement below re-asserts the frozen md5s — but recorded because a shared `~/.spacecrafter` is a confound for any md5-based assertion.
