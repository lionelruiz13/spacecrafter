## (a) The census, and two standing beliefs it corrected before anything was touched

`harness/f70_ascii.py` enumerates all **1498** tracked regular files of the code
repo and reports, per file, how its bytes decode and WHERE the non-ASCII ones
sit — comment, string literal, char literal, code, or prose. That last column is
the whole point: the sweep's safety argument rests on telling a comment from a
literal, so the instrument had to do it before the boundary could be drawn.

**Pre-state**: 937 ASCII, **561 non-ASCII** (339 text + 222 binary). Re-derived
against round-open `e2c8477b` by reading blobs out of git rather than checking
anything out: **zero files entered or left the set**, so F68 and F69 added no
non-ASCII, as their prompts bound them.

**Correction 1 — `app_command_interface.cpp` and `.hpp` are NOT ISO-8859 files.**
The standing rule (CLAUDE.md, §0.5, §11.188(k)) calls them the two ISO-8859
members of `src/`. Measured: each is **valid UTF-8 except for ONE stray 0xA7
byte** — a Latin-1 section sign — and `git log -L` attributes both to code
`2b8ec034`, one commit that wrote a Latin-1 § into two otherwise-UTF-8 files.
That single byte is what makes every UTF-8-aware tool classify the whole file as
binary. It also makes the task section's proposed method **wrong**: decoding
either file wholesale as Latin-1, as the section instructed, turns its REAL
accents into mojibake — the UTF-8 pair `C3 A9` comes out as two characters
`Ã` + `©` instead of `é`, and a per-character map would then have transliterated
the mojibake instead of the accent. The instrument decodes greedy UTF-8 with a
per-byte Latin-1 fallback, so one decoder serves the mixed files, the genuinely
ISO-8859 ones (`planetsephems/*`, isolated `0xE9` bytes) and the UTF-8 majority,
and the census and the converter cannot disagree (I2). The encoding classes were
widened to name the distinction: `utf8` / **`mixed`** / `iso8859`.

**Correction 2 — a SECOND grep hazard, beside the ugrep `-I` one already on
record.** `/usr/bin/grep -P '[\x80-\xff]'` under a UTF-8 locale matches CODE
POINTS U+0080..U+00FF, not bytes. It finds the accents and misses everything
above: measured **0 hits** on FTXUI's `border.cpp`, a file made of box drawing.
So the obvious byte-class grep silently under-reports exactly the characters a
D14 sweep must not miss. `LC_ALL=C`, or read bytes.

**Correction 3 — the dispatch's "199 tracked files".** It does not reproduce
under any whole-tree definition; measured at `e2c8477b` the figure is 561 (all)
or 339 (text). Reconstructed exactly: **199 = the text non-ASCII files outside
`util/ doc/ data/ include/ iniparser/ www/ sts-extension/`** — the engine-core
subset (src 171 + shaders/src 18 + planetsephems 6 + 3 root + cmake 1).
Reported, not aborted on: §11.179(a)'s ruling applies, because the census is
this task's own OUTPUT and the figure is a label the task re-adjudicates. The
part of that premise the work does stand on — that nothing changed between
round-open and the executor's HEAD — was verified and holds at zero delta.
Counterfactual, stated as the gate requires: had the 199 been an INPUT (a list
of files to convert), it would have been an abort.

## (c) The sweep is TWO rules, and the split between them is the whole safety argument

**Rule (1) — PROSE is transliterated.** Comments, markdown, JSON documentation
values, plain text, and every non-C-family file go through
`harness/f70_map.tsv`. That is the mandate's own clause; a comment has no
consumer but a reader.

**Rule (2) — a STRING LITERAL in C-family source is NOT transliterated.** Its
characters are re-spelled as `\xNN` escapes of the SAME bytes. The compiled
program emits byte-for-byte what it emitted before, and the source is
nevertheless pure ASCII.

Rule (2) exists because a literal is not prose, it is an OUTPUT, and the traced
consumers say so:

- **the DOME.** `oss << truncf(alt) << "°"` draws the altitude label;
  `skyDisplay`/`skyline`/`skygrid`/`utility` do this at **22 sites**.
  Transliterating would put `45deg30'00"` on the planetarium's screen where a
  degree sign is drawn today — a user-visible change on a shipped surface, which
  the task's own boundary forbids.
- **the TCP WIRE.** A `debug_message` reaches a `$DIAG` subscriber (§11.188), so
  a refusal string's bytes are protocol-visible.
- **a PINNED FIXTURE.** scedit's lint/doc/ui records pin the exact bytes of its
  messages, and `ui_gate.cmake` says of its own record *"never regenerating it
  blind"*.

Under rule (2) none of those move, and none of them had to be adjudicated one
literal at a time — which is the difference between a sweep and sixty judgment
calls.

**The escape is not this sweep's invention.** The same tree already writes
`"\xC2\xB7 Tab complete "` (`sc_tui.cpp:640`) and `"...Caf\xE9" "\tx\r\n"`
(`sc_tui.cpp:1215`) by hand, for exactly this reason. The second also
demonstrates the **string-splitting guard** the converter re-derives: a hex
escape swallows a following hex digit, so `"%d°E"` becomes `"%d\xc2\xb0" "E"`
(`skygrid.cpp:277`) — visible in the diff, and the converter REFUSES rather than
guesses when the language has no such guard (adjacent literals do not
concatenate in TypeScript, PHP or CSS) or when the literal is a raw string,
where no escape exists at all.

## (e) The map: standards where they exist, choices said out loud where they do not

`harness/f70_map.tsv`, **82 rows**, each with a mandatory note (a row without one
is rejected at parse). glibc's `iconv -t ASCII//TRANSLIT` is the baseline
wherever it has an answer — measured, it yields `...` `x` `+-` `(C)` `->` `e`
`>>` `|` `<=` `--` `.` and a bare `?` for the section sign, the degree sign and
every Greek letter. Where it answers, the map agrees. Where it does not, the row
says so:

- **`§` → `S`** (glibc: `?`). `S11.169` stays readable at one character against
  1134 occurrences.
- **`°` → `deg`** (glibc: `?`). Every PRINTED degree sign lives in a literal and
  is escaped, so no on-screen angle changes.
- **`·` → `*`** — a **deliberate deviation** from glibc's `.`: all 96 occurrences
  in the CONVERT set are multiplication or composition dots in mathematical
  comments (`R'*(offset-free eye pos)`, `Z(g1)*X(g2)*Z(g3)`), and `.` would read
  as C++ member access at exactly those sites.
- Greek letters are named (`pi`, `alpha`, …); `ᵀ` → `^T`; `Ẇ` → `W_dot`, because
  plain `W` would delete the derivative; `x̂` → `x_hat`.

**Six damaged sequences are repaired as units**, not character by character,
each from a citation inside this same tree: a degree sign UTF-8-encoded three
times over (`utility.cpp:249`), and two author names whose accents had already
been destroyed into U+FFFD before this sweep — now **`Chereau`** and
**`Jerome`** rather than `Ch?reau` and `J?r?me`, spelt from `planetsephems/
pluto.c:3` and `util/Atmosphere1/CMakeLists.txt:12`. That repair also produced
the sweep's one real bug and its fix: a multi-codepoint key may BEGIN with an
ASCII character, and the converter's ASCII fast path skipped ahead of it, so the
first pass emitted exactly the `Ch?reau` the row exists to prevent. Keys are now
matched before the fast path; the failure and its cause are recorded at the
function.
