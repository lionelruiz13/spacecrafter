# INTENT §11.52

52. **Vixy round-5: A31b write-back contract, parity criterion sharpened, enabled extension (2026-07-21, same day).** The three §11.51 residuals that were Vixy's close; verbatim quotes are the authority.
    - **(a) A31b RESOLVED — user-file write-back AUTHORIZED, under a three-clause contract** [vixy: *"write-back only when needed, and write as a different file then rename to ensure write succeed (ex : if disk is full, it could discard everything, we don't want this). It must only be operated on clean file, without anything ill-formed, otherwise it risk destroying ill-formed syntax."*]. **⚠ CLAUSE 3 SUPERSEDED [vixy 2026-07-22, §11.66(b)]: the "clean-file precondition ⇒ NO write-back" (protect-by-abstention) is REPLACED by protect-by-PRESERVATION — rewrite preserving malformed + unused fields + comments, with inline comment annotation of errors/defaults/valid-values. Clauses 1 (only-when-needed) and 2 (atomic temp+rename) STAND. The write-back itself moved from B28 to B31.** Original text kept below for provenance: (1) **Only when needed** — a critical key is absent (§11.51(d)'s criterion: keys that determine what is possible); never a routine rewrite. (2) **Atomic** — write a sibling temp file, then rename; the disk-full case must discard the *temp*, never the original [derived: rename atomicity holds same-filesystem only, so the temp lives in the target's directory, not /tmp]. (3) **Clean-file precondition, WHOLE file** — any ill-formed content anywhere ⇒ NO write-back for that file (a rewrite would destroy what didn't parse), plus a §2(f)-conform diagnostic naming what is ill-formed and the action to fix it. [derived design direction for B28, from the mandate's reason: prefer *text-preserving insertion* (add the missing key, leave every other byte) over model re-serialization — it minimizes the destruction surface the precondition guards against; the precondition stays mandated regardless.] Scripts remain out by §2(b), unchanged.
    - **(b) Parity meta-rule CONFIRMED + SHARPENED — perceptual parity, conditioned on physical exactness** [vixy: *"it must be as-if it was true from reasonable vision capabilities, and only if it was already physically exact. Defect which didn't reliably represent reality shouldn't hold and must be tracked as such."*]. Two-condition criterion: (1) equivalence level = **reasonable vision capabilities** — perceptual, not bit-level (the A/B channel's px>N thresholds were already this in practice; now it is the stated criterion, not a tolerance); (2) parity domain = behaviors where old was **already physically exact**; where old had a defect that didn't reliably represent reality, the behavior **must NOT be reproduced** and **must be tracked as a defect**. The §11.51(f) tension dissolves: the named-divergence channel is not an *exception* to the meta-rule — it IS the meta-rule's mandated tracking mechanism for the defect class; the ratified divergences (TAIL extent §11.43, name-on-disc §11.24a, §6.8(A) itself) all sit in the defect class and stand without re-examination. [derived reading, labeled: for pure semantic-surface questions with no physical referent — e.g. B29's reload semantics — the physical-exactness condition is vacuous and parity governs unconditionally; transparent substitution is the operative intent there.]
    - **(c) Enabled extension RESOLVED: same name minus `.disabled`; `.ini` for now** [vixy: *"The enabled format extension is the same without the .disabled extension, it will be .ini at first to keep the initial convention for now. If something better land, we'll change, that's lightweight change because it's a format change, not a structural content change, so it would only change the parsing, never the capability."*]. Concretely: `modularSystem/X.ini` = enabled, `modularSystem/X.ini.disabled` = generated inert twin; adoption = strip `.disabled`. **The stated principle is load-bearing for B24's design**: format is parsing-deep only — a format change must never be a capability change ⇒ the parser must be a thin, swappable layer over the capability model (I1: the capability model is the contract, a format is one implementation of it). Parser/content separation in B24 is now a requirement, not a style choice.
