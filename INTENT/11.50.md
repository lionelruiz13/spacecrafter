New path = explicit module composition, *"does the same thing and more"* — this is the ex-§6.7 D2 grammar, no longer optional and no longer a general-grammar-for-its-own-sake (its justification is now a stated population: people who wanted to do things the legacy format could not express *reliably*).
      **The migration mechanism, and it is more than pedagogy** [vixy]: *"Ideally, the old file generate the new one with an extension `.disabled` so that the equivalence can be quite visible and the new model became natural to modify for new data which could never have landed by design."* Three properties in one mechanism: (i) **inert by construction** — `.disabled` is not loaded, so generating it can never change what a user sees; (ii) **self-documenting in the reader's own data** — the new model is taught by showing the user their own bodies expressed in it, which is transmission at the recipient's model rather than at the sender's; (iii) **derived, and therefore an equivalence TEST** — if loading the generated file does not reproduce the legacy load exactly, the new grammar has a gap, and that is a mechanical, always-available coverage check over the whole shipped corpus (a stronger verification surface than any hand-written case list, and it costs nothing extra once generation exists). **Open sub-decisions → A32**: the new format's name/extension; where generated files land (writing next to user data touches their directory); regeneration policy (every load / on source change / only when absent); and the **I2 trap** — if a legacy file and its enabled generated twin both exist, two authorities describe the same bodies, so the rule must be explicit (enabling retires the legacy file, or the loader refuses both) rather than discovered by whoever hits it first.
    - **(c) Dual-path default FLIPPED + `beta_features.ini` created [vixy 2026-07-21, implemented this session]**. Was: `drawModularSystem = false` with a 1 s auto-alternation — *a comparison harness running as the product default*, which every unconfigured launch experienced as flicker. Now: **new path, pinned, by default**; alternation is opt-in. **Where the flag lives was a real question and it is settled by a code fact, not taste**: `config.ini`'s key set is a **migration contract** — `CheckConfig::checkConfigIni` rewrites a user's config on version mismatch and injects every schema key [observed: mainModule/checkConfig.cpp:467-497] — so a key added there is expected to live forever, and retiring an experiment would either orphan keys in every user file (`checkUselessSection` is commented out) or keep dead ones. Experimental flags have the **opposite lifetime** by definition. Therefore a separate optional file: **`beta_features.ini`**, never written back, **absence == every default**, retire-by-deleting-a-line, and it doubles as the enumerable inventory of what is currently experimental. Vixy's constraint carried into the header: *a flag lands there only when the choice is actually relevant to someone*, not one per experiment by reflex.
      **Implementation** [all header-documented, I1]: `SSystemFactory::RenderPathMode{NEW,OLD,ALTERNATE}` + `setRenderPathMode` (member defaults `drawModularSystem=true`, `pathPinned=true` — the no-configuration behaviour, kept consistent with `NEW`); `AppSettings::loadBetaFeatures` returns false when the file is absent **after an explicit presence check**, because `InitParser::load` calls `exit(-1)` on a missing file [observed: tools/init_parser.cpp:54-64] — correct for `config.ini`, fatal for an optional one; `Core::setRenderPathMode(string)` **refuses an unrecognised value with a log line instead of falling back silently** (a typo'd flag must be visible, not absorbed); read in `App::init` beside the other config reads (one place where startup state comes from files). Lifetime verified: `ssystemFactory` is constructed in `Core`'s ctor (core.cpp:100), `core` in App's ctor (app.cpp:159), both before `App::init` (app.cpp:572); no other site writes either flag.
