## (b) The condition is asked of `where()`, not of `channel` — a deviation, stated

§11.187(d) recorded the reversal as `channel != TCP` → `channel == NONE`, and
§11.191(b) ratified *"the one condition F68 predicted"*. The delivered guard is

```cpp
const std::string where = currentOrigin.where();
if (where.empty())
	return std::string();
return where + ": ";
```

**Behaviour-identical on every origin this engine can produce**, and the check
is not an appeal to plausibility: `ScriptOrigin::fromFile` is the ONLY producer
of a FILE origin `[observed: script.cpp:119 — the one call site, confirmed by a
tree-wide grep for `fromFile`/`ScriptOrigin(`]`, it is reached only after the
`ifstream` opened (so `file` is non-empty) and `lineNo` is pre-incremented from
0 before the first use (so `line >= 1`) `[observed: script.cpp:99-120]`.
Therefore `valid()` holds for every FILE origin in existence, `where()` is
non-empty for it, and `channel != NONE` and `!where().empty()` cannot differ
today.

What the `where()` form buys is that they cannot differ TOMORROW either: a
producer that one day builds a FILE origin without a path or a line yields NO
tag instead of a bare `": "` prefix on a diagnostic line. And it removes a
second encoding of one question — the header already says *"a reader that wants
to NAME asks `where()`, one that wants to WRITE asks `valid()`"* (§11.187(b)),
and `originTag()` is precisely the reader that wants to name. Asking `channel`
here would restate `where()`'s emptiness rule at a second site, which is I2's
shape at the level of predicates.

**Both readings recorded, and the deviation is the executor's**: the literal
form has its own merit — a reader arriving from §11.187(d) finds the condition
it predicted, spelled the way it was predicted. If the owner prefers the literal
form, the edit is one line and no gate leg changes.

## (f) The instruments gained a declared era, and that is a defect class closing

`f68_provenance.py` and `f69_feedback.py` are re-run by every later task that
touches this surface, and by then their "pre" binary is not the one they were
written against. F70 hit this squarely: it ran `f69_feedback.py` against an
f69-era pre binary and took **three known-false reds** (`vi-pre` D's wire empty,
`vi-pre` three unrecognised commands, `ix` scedit's opposite expectation)
`[observed: artifacts/f70/wire/f69_result.json, all_ok false, 46/49]`. Nothing
was wrong with the engine; the instrument was asserting a claim about a binary
that no longer existed.

§11.191(c), ruled the same day: a false positive in a gating instrument is a
defect class to eliminate at its root, never a price paid for failing closed.
So the era is now an **input**: `SC_PRE_TAGS` (`none` | `tcp`) in f68,
`SC_PRE_ERA` (`f68` | `f69`) in f69, defaulting to the current one, documented
in each docstring with the sha range it names, and printed before the run.

**Declared, never inferred** — and that is the load-bearing half. An instrument
that read the era off its own pre-phase would make every pre-side leg assert
whatever it happened to measure, which is a green that cannot fail. A wrong
declaration turns those legs RED; it cannot turn a red run green.

One honesty cost is recorded rather than hidden: under `SC_PRE_ERA=f69` the
scedit leg (`ix`) has the SAME expectation in both phases, so it no longer
discriminates by opposition. The leg says so in its own text, and names what
carries the discrimination in that era instead (the `iv-D` / `vi-pre` wire
identity legs).
