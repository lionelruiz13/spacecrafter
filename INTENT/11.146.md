## (a) The owed item, and the answer

§5.77 owed one thing before it could be judged: *"an enumeration of the other
startup paths that report only on `stderr` would size it."* The row also wrote

## (b) The instrument: a census, then one launch that measures the word "startup"

Three surfaces, each answering a question the others cannot.

**1. The census — `f36_enum.py`.** A grep is not an enumeration here, twice over:

- **Comments.** `grep 'std::cerr\|std::cout' src/` returns **335** hits (**307**
  outside EntityCore). Only **138** of the project ones are live code: **169 are
  commented-out debug prints**, two of them (`checkConfig.cpp:505,508`) inside a
  `/* … */` block that a per-line `//` test cannot see. A grep-based sizing of
  this row would have been **2.2×** the truth. The enumerator therefore strips
  comments with a real character-state machine (code / `//` / `/* */` / string /
  char), so `std::cout << "// not a comment"` survives and `// std::cout << "x"`
  does not.
- **Channels.** Matching only iostreams misses `printf`, `fprintf(stderr, …)`,
  `puts` and `SDL_Log`. `sprintf`/`snprintf`/`fprintf(<file>, …)` are excluded by
  negative lookbehind and by requiring the stream argument.

Result `[measured: harness/artifacts/f36/f36_sites.json]`: **214 live
console-output sites** — **186 project**, **28 EntityCore** (read-only for this
task: part of the sizing, not of any fix) — in **76 distinct enclosing
functions**. By channel, project: `std::cout` **105**, `printf` **45**,
`std::cerr` **33**, `SDL_Log` **1**, `puts` **1**, `fprintf(stderr)` **1**.

**2. The startup boundary — `f36_probe.py` + `f36_reach.py`.** "Startup path" has
a measurable meaning and a guessable one. The measurable unit is **not the line**:
a failure-report line does not execute on a healthy startup, so reading a good
launch's console output enumerates the sites that FIRED, never the sites that
COULD. The unit is the **enclosing function** — *was it entered before the app
reached its main loop?* One self-disabling `gdb.Breakpoint` per function (`stop()`
records, disables itself and returns False, so the inferior is never left stopped
and a breakpoint on `FilePath::FilePath` costs one stop for the whole run), and
**the boundary itself is a breakpoint** on `App::startMainLoop` — the call at
`main.cpp:348`, after `app->firstInit()` — which only flips the stamp every other
hit carries. "During startup" is therefore read off the same channel as the hit,
not applied afterwards as a judgment.

Coverage is reported, not assumed: the probe emits a MANIFEST line per breakpoint
with its resolved location count, because an unresolved breakpoint and a function
that is genuinely never entered otherwise produce the identical evidence —
silence, the silent-no-op probe class (§11.47).

The launch is F27's `Session` (I2 — same farm, same `/proc/<pid>/comm`
concurrent-instance assert, same frozen md5 pair) with F31's `launch_prefix`.

**3. The applog, as the second surface AND the probe's check.** `Session` already
captures stdout+stderr merged in order. It is the positive control: every line the
app printed must attribute to an enumerated site. **It earned its keep** — see
§(d).

Run: one fresh launch under gdb, **app exit 0**, **boundary seen**, **77
breakpoints, 2 unresolved**, binary md5 `85b0d12312ba7fd8b776a008513bbf9d` at code
`eb11432e`; concurrent-instance probe **0** before launch; **frozen md5 in == out**
`[measured: artifacts/f36/f36_result.json, f36.applog]`.

## (f) Why the class does NOT admit ONE uniform, purely additive routing

Every one of the 37 carries a blocker `[measured: f36_class.json]`:

| blocker | n | what it is |
|---|---|---|
| `DUPCONSOLE` | 15 | the site writes **stderr**, and `cLog` at `L_ERROR` **already writes stderr** whenever `print_log` is set — so the call prints the SAME line TWICE on a non-log observable |
| `FRAGMENT` | 13 | the message is a newline-less sentence fragment composed on the console with its neighbours; alone it is not a diagnostic |
| `PLATFORM` | 4 | the `#else` of `#ifdef __linux__` — not compiled here at all |
| `CONSOLEADD` | 2 | writes stdout/`SDL_Log`, so not a verbatim duplicate, but under `print_log` a `cLog` call still ADDS a console line |
| `PRELOG` | 2 | executes **before** the log exists |
| `SELF` | 1 | the report IS the logging subsystem failing |

Three of these are **structural and objective**, not matters of taste:

1. **`PRELOG` — the fix would crash.** `cLog::openLog` runs at `main.cpp:209`;
   `CallSystem::checkUserSubDirectory` runs at `main.cpp:199`. `cLog::write` ends
   in `logFile.at(LOG_FILE::INTERNAL)` `[observed: log.cpp:150-156]`, which throws
   `std::out_of_range` on an empty map. Routing those two sites through `cLog`
   would abort the app on the very path that reports a failed install copy.
   Note the shape the code ALREADY uses there: the SUCCESS messages of that same
   function go to an `out` accumulator that `main.cpp:223` logs once the log is
   open `[observed: call_system.cpp:146,154]`. So the right fix for those two is a
   *different mechanism* from the right fix for the rest — which is the definition
   of a non-uniform class.

2. **`FRAGMENT` — the fix would need new wording.** `ZoneArray::create` composes
   one console line out of pieces: `printf("byteswap ")`, `printf("unsupported
   version, ")`, `printf("no memory, ")`, `printf("bad file type, ")`,
   `printf("initialization failed\n")` — the sentence's head,
   `printf("Loading %s: ", …)`, is **commented out** at `zone_array.cpp:110`, so
   the remaining fragments already print unattached. `cLog::write("no memory, ")`
   is not a diagnostic, it is noise with a timestamp; making it one means writing
   a new message, and §2(f) (actionable diagnostics) is exactly the standard that
   forbids doing that mechanically. 13 sites.

3. **`SELF`** — `cLog::openLog`'s own `std::cerr` reports that the log could not
   be opened. There is nowhere to route it.

And the fourth is **measured, not argued**: `DUPCONSOLE`/`CONSOLEADD` (17 sites).
`cLog::write` calls `writeConsole` when `isDebug` `[observed: log.cpp:122-123]`,
`writeConsole` sends `L_ERROR`/`L_WARNING` to **`std::cerr`**
`[observed: log.cpp:206-210]`, and `isDebug` is `conf.getBoolean(SCS_DEBUG,
SCK_PRINT_LOG)` `[observed: main.cpp:262]`. **`print_log = true` in the INSTALLED
`~/.spacecrafter/config.ini`** `[measured 2026-08-09, cited fetch]`, and **654
`cLog` lines went to the console on this run**.

That the two authorities differ is not derived from the code — **all four cells
were measured on this one launch**, on the two messages that sit three lines apart
in the applog `[measured: f36.applog:2010-2011 vs
farm_f36/.spacecrafter/log/spacecrafter.log]`:

| the write | console (applog) | `spacecrafter.log` |
|---|---|---|
| `cLog` `L_ERROR` — `UI: ERROR - Failed to acquire texture data for icons` | **2** | **2** |
| raw `std::cerr` — `Invalid sky culture directory: western-spacecrafter` | **1** | **0** |

A `cLog` `L_ERROR` already reaches BOTH surfaces here. So adding one beside the
existing `std::cerr` gives 1 + 1 = **two console lines** and one log line — the
duplication is a measurement of the two rows above, not a prediction.

So at `core.cpp:1430` the row's own proposed one-liner would put on stderr:

```
Invalid sky culture directory: western-spacecrafter
(Error): Invalid sky culture directory: western-spacecrafter
```

— the log gains, and **a non-log observable changes too**, which is precisely what
the task's discriminating check forbade (*"stderr's pre-existing lines unmoved …
the log gains, nothing else changes — D8 as-if on every non-log observable"*).
Avoiding the duplicate means removing the raw `std::cerr`, which the same mandate
forbids (*"nothing removed"*) and which would in any case silence the console for
every install that sets `print_log = false`.

**This is the decision the row must be handed, and it is Vixy's** (§(j)): the
codebase has **two console authorities** for the same events — `cLog` (which
writes the console only when configured to) and the raw streams (which always do)
— and there is no additive move that does not either duplicate output, delete
output, or reword it. The proof that the two authorities collide is in the
artifact: at `f36.applog:1065` a `fprintf(stderr, …)` cut a `cLog` console line in
half mid-word —
`(Info ): Composed twin of ./stel` + `ZoneArray::create(stars_2_0v0_8.cat): fopen failed`
— two unsynchronised writers on one file descriptor (I2).

The applog's direct-to-console output (cLog lines and gdb noise removed) is **180

2. `ZoneArray::create(stars_2_0v0_8.cat): fopen failed`
3. `ZoneArray::create(stars_3_1v0_4.cat): fopen failed`

**(2) and (3) are not cosmetic.** `~/.spacecrafter/stars.ini` names four

The mechanism is a split authority, and it is code, not field: the catalogue

and `stars_3_1v0_4.cat` `[measured, cited fetch: md5
0aec3e72c25cd709abb46e37a6c924af]`, `/usr/local/share/spacecrafter/stars/` carries
`stars_2_0v0_5.cat` and `stars_3_1v0_3.cat` (7 files total), and
`~/.spacecrafter/stars/` — which is NOT where the loader looks — does carry the

**A fourth failure reports NOWHERE, not even on the console.** The same

## (j) The decision this hands to Vixy

The row asked for a size so the fix could be judged at the class. The size is 37,
and the judgment turns on ONE question that is not an executor's to answer:

**Should a startup failure appear on the console twice when `print_log = true`?**

- **Yes** ⇒ the additive `cLog` call lands at all 20 non-`PRELOG`/`SELF`/`PLATFORM`
  sites, 13 of them needing new wording first (§(f).2).
- **No** ⇒ the fix is not additive: either the raw stream write is removed at each
  site (changing the console for `print_log = false` installs), or `cLog` grows a
  way to say "log only, the caller already printed" — a new interface, B28-adjacent.

Everything downstream of that answer is mechanical; nothing upstream of it is.
A related sub-question, since it decides 2 more sites: should the pre-log window
(`main.cpp:188`–`209`) keep reporting to the console only, or should the `out`
accumulator idiom that already exists there be extended to the failure paths?
